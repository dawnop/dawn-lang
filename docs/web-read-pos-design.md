# web 8 的流读取位置协议

> 状态：**current**，web 8 顺序源位置协议、迁移与验收结果。

## 原因与协议

web 7 的 `BodySource.read(n)` 把游标交给源。纯 Dawn 的闭包不能修改捕获的变量，
文件只能按 `read_range(path, pos, n)` 读取，因此该接口迫使调用方额外保存状态。
web 8 改成 `read(pos, n)`：服务器从 0 开始，每次以实际返回的字节数推进位置，
空字节表示 EOF；短读不表示 EOF。位置是源内的字节偏移，不是 HTTP chunk 或请求偏移。
协议只支持一次顺序消费，不承诺重放或随机访问，与 `Transport.read(pos, n)` 一致。

两个服务器的响应泵都持有累计字节数，分别把该数传入源。JVM InputStream 已经维护顺序
游标，adapter 忽略 pos，保留等待首字节、随后只读取已就绪字节的行为。
`pump_with` 的 bracket 与 HEAD/无体状态的 `drop_body` 继续负责恰好一次 close。

## 源与迁移

新增纯 Dawn 模块 `web/source`：`bytes_source` 对 Bytes 切片；`file_source` 每次安装
Fs handler 并调用 `read_range`，不持有文件句柄，不缓存文件或在闭包里保存可变状态。
文件读失败必须终止响应，不能伪装 EOF；Result 的 Err 转成带原始消息的 panic，
现有泵屏障记录失败并关闭源。源本身不拥有文件，close 无操作，删除文件由调用方的
close 包装或外层 bracket 负责。读取期间文件必须保持不变。

包身份 `web7` → `web8`，版本 8.0.0；`web_jvm` → `web_jvm2`，版本 2.0.0。
依赖别名 web/web_jvm 和模块路径不变。所有仓内记录字面量、直接 read 调用、测试夹具一起迁移，
不保留旧签名。英文 README、CHANGELOG 与迁移文档列明调用方与同 tag 依赖要求。
dawnop-site 等正式 tag 后在 S7 升钉，当前生产版本保持其已钉版本。

## 验证方案

保留原 78 条线协议契约；新增位置源多次短读、Bytes/文件、HEAD、定长、chunked、
短流、长流、读失败及关闭记录。断言独立检查预期内容和关闭次数，不能只比较两臂。
四类负控分别破坏偏移推进、偏移加一、close、HEAD 的禁止读取，要求专属用例报红；
两臂均实际构建和运行变异体。另以 256 MiB 文件上传并回传，分块计算摘要、测峰值 RSS，
小输入与大输入对比。新增工作复用既有契约入口与构建产物，
不增加 workflow job 或 push-total 预算；若超预算则先优化或重分配后验收。

## 实测结果（2026-10-22）

JDK 21 与 v0.97.0 native 编译器运行同一应用：原 78 条框架契约通过，新增 11 条
位置/关闭断言通过。四种新变异在两后端各构建一次，8/8 都被专属断言杀死；原四种
变异仍然全部被杀死。包测试：JVM web 84、web_jvm 114（含依赖）；native web 84。

256 MiB chunked 上传落盘，再由位置文件源按定长响应下载。两后端上传/下载摘要均为
`f858f6c1cf1835bbc7e4a964df481101b614c6f0c92cb09ab11bcd5669418246`。
4 MiB 与 256 MiB 的峰值 RSS：JVM 78.4 / 80.2 MiB，native 22.1 / 22.1 MiB。
JVM 固定 32 MiB heap、SerialGC、C1 和预触页，排除堆扩容与 JIT 暖机对差值的干扰；
这证明此配置下的有界内存，不推导吞吐或生产 RSS。阈值：JVM <160 MiB、native <32 MiB，
大输入相对小输入增长 <32 MiB。Python 分块产生带递增块序号的数据并分块核对 SHA-256，
避免周期数据掩盖错块。文件和 request spill 全部清理。

整套契约本机 81 秒；旧步骤已计入 90+20 秒预算，当前测量未超过既有计入值。
复用入口、不改 workflow 或 steps lock、不增加 push-total；仍须以最终全套门禁为准。
原 78 条契约保留原归一化与已知 JDK 差异，不声称 HTTP 响应逐字节完全相同。
文件读取失败用已知长度验证提前 EOF 与 close，未知长度源的 JDK 失败信号仍有原先限制。

## 不做的（理由）

- 不增加文件句柄、可变全局或闭包内隐藏的 Mem 状态；游标属于泵。
- 不修 Mem 围栏问题 #847；与此协议独立。
- 不实现并发读取、重试、seek 或 HTTP 客户端；接口只描述一次顺序消费。
- 不修改 tileir、不发版、不部署、不发布证据；后续由协调者安排。
