# The failures this map exists to have caught, replayed on the trees they
# happened on.
#
# Not a restatement of them: each stanza names commits, gatemap.py materialises
# those trees out of git and runs the whole map on them. A rule that stops
# producing the verdict below fails here, and so does a fixture whose
# expectation stops matching anything.
#
# Every stanza also carries `ground` lines, which are claims about the history
# rather than about the map, measured with git. Without them a fixture could go
# on describing an event that never had this shape, which is the failure mode
# this whole directory is about.
#
# Keys: tree (a commit), overlay (<commit> <path>, for a batch whose tree never
# landed as one commit), ground (see parse_fixtures), query (a path to ask
# about), expect / reject / only (<level> <substring of "<gate> :: <reason>">).


# 2026-08-11, the first of two. The pipe batch (ba93e76, 3c51ae1) pinned a
# negative control to a whole sentence the std loader prints; the std batch
# (9e64179) rewrote that sentence. Neither batch could see the other, and the
# tree below is the one the pipe batch was green on: main before the loader
# change, with the pipe batch's own directory on top.
#
# What the map has to say, from either side, is that the contract and the
# compiler module share a string. Asked about the module, it names the contract
# that spells the string out; asked about the contract, it names the module.
name: 3c51ae1 and 9e64179, the sentence two batches shared
tree: 9e64179^
overlay: 3c51ae1 scripts/pipe-contract
# the shared sentence, on both sides, and the commit that broke the pair
ground: contains 3c51ae1:scripts/pipe-contract/run.sh bundled std module `
ground: contains 9e64179^:selfhost/src/driver/stdlib.dawn bundled std module `
ground: lacks 9e64179:selfhost/src/driver/stdlib.dawn bundled std module `
ground: touched 9e64179 selfhost/src/driver/stdlib.dawn
query: selfhost/src/driver/stdlib.dawn
expect: coupled scripts/pipe-contract/run.sh spells out 'bundled std module `'

# 2026-08-11, measured rather than reasoned. The v0.64.0 branch declared twelve
# Emit-Change labels; five changes confined to corpus content named oracles
# that could not have seen the difference. Both `emit <target>` output legs
# compile the same working tree, so a change to a corpus's own source is said
# identically on both sides and cancels. The driver-module case already in this
# file is the special case of that, not the whole of it.
#
# Confirmed here by mutation, with a positive control: a new `pub fn` appended
# to packages/web/src/server.dawn reaches the emitted server.class (grep finds
# its string there), and `emit packages/web` still reports the two sides
# identical. The ground lines below are the two legs of the loop that makes it
# so, which is the part git can check.
#
# The rejection is the point. prev-diff does read packages/web, so it is
# `coarse` there, and a reader who stops at that line writes the declaration
# this stanza exists to prevent. What it must never be is `exact`.
name: 9b4c9f8, a corpus target is blind to its own emit label
tree: 9b4c9f8
ground: contains 9b4c9f8:scripts/emit-labels.txt emit packages/web
ground: contains 9b4c9f8:scripts/selfhost-prev-diff.sh "${PREV[@]}" __emit "${PREV_STD[@]}" "$t"
ground: contains 9b4c9f8:scripts/selfhost-prev-diff.sh "${HEAD_BIN[@]}" __emit "$t"
query: packages/web/src/server.dawn
expect: blind `emit packages/web` compiles this same source in both output legs
reject: exact N vs N-1 differential
