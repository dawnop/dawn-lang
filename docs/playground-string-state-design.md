# Playground 插值字符串的词法状态

> 状态：**current**。issue #83 的字符串与插值词法状态修复。

## 问题与根因

`println("hello form $name")` 在编辑器里跳过调用的右括号，向后找到闭包的右花括号。
真实 CodeMirror 语法树与 matchBrackets 的复现表明，这不是编译器解析错误：
stream tokenizer 在字符串遇到 `$` 时返回，却没有保留双引号字符串状态。
后面的结束引号因而成为新字符串的开始，把右括号吞进字符串 token。
三引号开头分支也会在保存状态前提前返回。

## 方案

用字符串与插值表达式的状态栈保存返回位置。普通字符串、三引号和 raw
字符串共用结束符扫描；插值表达式按正常代码分词，花括号深度决定何时回到
外层字符串。内层字符串、注释和转义不改变外层插值深度。
CodeMirror 的状态复制必须深复制栈，避免增量解析修改之前行的缓存状态。
未结束的普通字符串在换行处恢复，保留已有编辑时容错。

回归使用真实 EditorState、完整语法树和 matchBrackets，不用补全扫描器代替。
覆盖原始闭包例子、连续插值、嵌套表达式/字符串、三引号与 raw、转义、跨行
与增量编辑。先在旧 tokenizer 上运行新测试，证明它们能捕获问题。

## 验收

同一套真实 EditorState / matchBrackets 测试注入父版本 tokenizer 后有 21 条断言失败，
包括原例左右两个方向、嵌套表达式/字符串与增量编辑。修复后全部前端自测通过，
并通过生产 bundle 构建。普通字符串、三引号、raw、转义、注释中的括号与空行恢复
都有正控；没有修改编译器、补全扫描器或依赖版本。

## 不做的

不改编译器语法、不改 LSP 协议，不顺带重写补全 lexContext，不加入新的依赖。
补全扫描器不是此次括号错误的来源；本次只改变编辑器真实 tokenizer 与回归。
