# Every Cx table read reachable from the seven body-checking entry points, and
# what accounts for it. scripts/journal-reads/check.py holds this file to the
# tree in both directions: a read that is not here fails the gate, and a row
# whose read has gone fails it too.
#
#   <module>.dawn::<fn>::<field> | <verdict> | <detail> | <reason>
#
#   logged     <detail> names the semantic_reads fact (or facts) that record
#              the answer, optionally as Fact@<site> when the recording happens
#              in a caller or a callee rather than here. The gate checks the
#              variant exists, that the named function still builds it, and
#              that the two functions still call one another.
#   product    <detail> names the Cx field body_product.assemble reinstalls
#              from the product, which is what makes the read body-local. The
#              gate checks assemble still writes it.
#   write      the read is the old value inside that same field's own
#              `Cx { .. }` update. <detail> is empty.
#   uncovered  a real hole. <detail> is `backlog`, or
#              `compensated-by=<site>` naming the admission-side guard that
#              re-asks the question; the gate checks that guard still reads
#              the field.
#
# A `logged` row proves a fact was recorded in a function on the same call
# chain. It does not prove the fact's answer determines this read's answer;
# that is what the reason column is for, and it is written by a person.
#
# Regenerate the skeleton with `check.py --record`. The reasons are not
# generated.
