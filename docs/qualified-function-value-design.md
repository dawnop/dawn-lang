# 模块限定函数值（#66）

已实现；方案先于代码记录，以下回填验证结果。

`helper.double(3)` 能调用，但 `apply(helper.double, 4)` 被当作不存在的导出值。
`check_expr` 的字段访问只尝试常量、构造器、Java 静态字段和普通值；限定调用
另查 `module_fn_sigs`，因此函数存在于调用路径却缺席值路径。

方案是在限定字段访问中查询同一张导出函数签名表，并交给已有的
`check_fn_value`。它保留签名的 owner、泛型的期望类型推断、字典展开和效果行；
无需增加语法、Typed AST 或后端分支。模块别名与局部值的判定沿用限定调用规则。

回归覆盖普通模块的高阶参数、泛型期望类型、私有函数拒绝，以及通过 `[deps]`
和重命名导入的包函数。双后端运行语料以手写输出验证最终 owner；恢复旧查询路径
必须使新测试失败。执行 selfhost 测试和相关 gate-map 门禁，Core 若移动由官方脚本
重录并核验；输出声明依据实际差分。

## 验证

- `dawn test selfhost`：595 项通过。将两个新测试移植到修复前的 `85e10bc7`，
  恰好这两个测试失败，其他 593 项通过。
- `scripts/spike-native/qual_fn`：JVM、native 与 ASan 通过，手写输出依次为
  `6`、`8`、`9`、`10`、`main.dawn`；修复前编译器拒绝四处限定函数值。
- Core 官方 `--record` / `--check`：17 份完整转储、87 个模块哈希通过。
  `exitmem` 的规范化哈希也移动：前面声明数量改变导致成对的 handler ID 整数移动。
  修复前编译器与修复后编译器对同一份新 selfhost 源码的 Core 转储逐字节相同。
- release 差分通过；对已被历史声明覆盖的输出另用真正的父提交编译器对拍，
  避免已有 `Emit-Change` 把新差异遮住。

## 不做的（理由）

- 不改函数值 ABI：问题发生在名称解析，还未进入 lowering。
- 不把效果操作变成函数值：其拒绝规则由 `check_fn_value` 统一持有。
- 不重构所有限定访问：常量、构造器与 Java 字段已有独立规则，扩大改动无助于修复。
