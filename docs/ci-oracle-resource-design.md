# 正确性门禁的资源判据

> 状态：**current**

正确性对拍中的短墙钟截止会把等待调度算成产品工作。并发负载下，同一份输入和输出可能因此得到相反判词。性能预算仍由 workflow 的声明与 job 墙钟停止器负责；子命令的正确性判词按实际执行、协议状态及输出判断。

`scripts/cpu-limit.py` 在执行命令前设置内核 `RLIMIT_CPU`，计入一个进程所有线程的用户态和内核态 CPU 时间。子进程继承同一额度，各进程独立计量；这不是整个进程树的累计 CPU 限额。已有更严格的调用方额度不会被提高。软限额后还有一秒 CPU 的硬限额，避免目标忽略软限额信号。阻塞 I/O 仍由外层 job 的原墙钟停止器终止，不能把这个包装器当作独立的挂起检测器。

native doc 的每次 native/JVM 调用沿用数值 30，单位改为 CPU 秒。退出状态和 stdout/stderr 的逐字节比较、受限工具环境以及错误分支都保留；比较前保存两端字节和原始返回码。

全样本 warm 使用同一包装器，沿用数值 180 作为可继承的逐进程 CPU 额度，不再另设全样本的 180 秒墙钟截止。样本全集、真实冷编译、run/C/JVM/tile 各答案、缓存命中与冷结果逐字节比较都保留；子阶段的产品超时也保留。整个 job 仍按原有 3× 预算设置墙钟停止器。

LSP framing 在 initialize 完成后开始观察拒绝阶段。在 Linux 上，五秒额度计入实际服务进程所有线程的 CPU 时间，RSS 采样和调度等待不计入。对当前 Linux x86_64 门禁，还会检查输入管道已空且服务线程阻塞于 fd 0 的 read：拒绝头已消费后再索取输入，本身就是协议失败，无须等到某个墙钟数值。非 Linux 保留原墙钟观察；其它 Linux 架构只是不使用 read 状态判据。固定错误回复、stdin 保持打开时退出、RSS 增量及整组清理断言都保留。

内核包装器自测使用真实 exec、进程暂停、计算循环及后代进程，验证等待不计费、失控计算会被终止、字节与返回码不变以及更严额度的继承。framing 自测分别使用计算循环、等待后续 stdin 和正常退出的服务替身，验证观察器没有把未退出当作成功。

stdin 观察使用线程的睡眠状态和前后两次 read(fd 0) 调用快照，并再次检查输入管道为空；不依赖内核等待函数的符号名。阻塞夹具先确认已消费输入，再以观察器自身的 CPU 额度约束观察循环；观察能力缺失必须明确失败，不能让夹具无期限挂起。每项观察器检查开始时立即输出标签，失败现场不再依赖整组自测结束后的缓冲输出。

C matrix 的每次命令在解析或断言前保存原始 stdout/stderr、返回状态、超时标志和资源观测。四份配对 wire body 在归一化比较前落盘并输出原有无损记录；失败时保留工作目录。语法探针保存每个 parse/check/fmt/lower/run/LSP 命令的 raw rc，并在失败时保留整个探针目录。取证不改变归一化规则、精确红集合或 mutant 覆盖判词；缺少历史 wire/rc 的失败不能仅凭重跑成功就定因为超时。
