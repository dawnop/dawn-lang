## 一、范围

站点搜索到刀 3 为止只搜标题：`search-<lang>.json` 一行一个可跳转的条目（stdlib 条目、规范与教程的节、设计史、
示例与页面），面板在 wasm reactor 里扫这些行。规范、教程和设计史的**正文**搜不到：搜 `handler state` 能找到
教程里那一节的标题，搜正文里才出现的词就是零。

刀 4 只做生成器那一半：把四份文档（规范、教程、时间线、早期设计决定）切成节和段落、分词、建倒排、出摘录，
写成第二份资产 `search-body-<lang>.json`，并让 `gen/links` 像核 items 一样核它的每个 href。查询（二分、交集、
中文候选验证、摘录高亮、懒加载）是刀 5，在 `examples/projects/tea_dom_search` 里。两刀之间只隔这份资产，
所以它的格式写在这里，两边的测试都引用本文的文字。

stdlib 不进正文索引：它的每个条目已经在第一段资产里带着签名和注释首句，`stdlib.html` 上也没有别的正文。

## 二、契约

### 2.1 资产

每种语言一份：`/assets/search-body-en.json` 与 `/assets/search-body-zh.json`，按内容指纹化
（`gen/fingerprint`），页面经属性拿到指纹名（2.4）。

顶层是**位置数组**，不是对象。理由与第一段资产相同（`site/src/gen/search.dawn` 头注）：本仓 JSON 渲染器里
对象的键序是哈希表的事实，`scripts/site-dist-diff.sh` 要求两条后端写出的字节逐一相同；数组只有一种顺序，
就是这里写的顺序。

```
[ version, sections, terms, postings, excerpts ]
```

| 位置 | 字段 | 形状 | 含义 |
|---|---|---|---|
| 0 | `version` | Int | 格式版本，**当前为 1**。格式变了就加一；reactor 不认识的版本就不加载正文，只搜标题。 |
| 1 | `sections` | `[[doc, href, title], …]` | 节表，下标即节号 `sec`（从 0 起）。 |
| 2 | `terms` | `["a", "ab", …]` | 词表，按**码点序**升序（2.3），无重复。 |
| 3 | `postings` | `[[gap, …], …]` | 与 `terms` 等长：`postings[i]` 是第 `i` 个词出现过的全部段落编号，升序无重复，**按差值写**：第一个数是编号本身，之后每个数是与前一个编号的差（恒 > 0）。还原就是求前缀和。 |
| 4 | `excerpts` | `[[sec, text], …]` | 段落表，下标即**段落编号**（从 0 起）。每个至少切得出一个词的段落恰好一条，按（节号，节内顺序）排列，所以编号随节号单调不减。`sec` 是它所在的节。 |

**`sections` 的三个字段：**

- `doc`：`"spec"`、`"tutorial"`、`"history"`、`"design"` 之一，说明这一节在哪份文档里。`history` 是时间线
  （`history.html`），`design` 是早期设计决定（`design.html`）。第一段资产把后两者都归在面板的 History 组，
  这里分开写，好让面板在摘录下面标出出处。
- `href`：站内、相对**站点根**的路径，不带前导 `/`、`./`、`../`，中文一律在 `zh/` 下。带锚点的节写成
  `spec.html#s6-5`、`tutorial/09.html#s0-2`；每页的「导言节」（2.2）不带锚点，就是页面本身
  （`spec.html`、`tutorial/09.html`）。与第一段资产的 href 同一规则，面板用同一个 `data-search-root` 拼接。
- `title`：节标题的纯文本（`html/render.inline_text`，与 TOC 显示的文字相同）；导言节的标题是页面标题
  （规范、时间线、早期设计决定取文档的 `#` 标题，教程章节取章名）。

**`excerpts` 的 `text`：** 该段落的纯文本，连续空白压成一个空格、去掉首尾空白。超过 120 个码点时截断：
在第 60 到第 120 个码点之间找最后一个空白，在那里截；这段区间里没有空白（中文段落常见）就在第 120 个码点处硬截；
截过的末尾加 `…`（U+2026，一个码点）。所以 `text` 最多 121 个码点；截过的一定以 `…` 结尾（段落原文本身以 `…`
结尾而没截的极少，查询侧把它当截过处理只会多保留候选，不会漏）。

### 2.2 节与段落

- **节**：每页一个导言节，加上该页每个**带锚点的 h2–h4**。导言节收的是第一个带锚点标题之前的正文
  （规范页的状态框、教程章节在第一个 `###` 之前的几段）。导言节即使没有正文也占一个节号，所以两种语言的节表
  在标题结构相同时逐条对应。
- 锚点不在这里重新计算：`html/render.render_doc` 在 `Doc.heads` 里按文档顺序交出每个带 id 的标题
  （h2–h4，比 TOC 多了 h4），生成器拿第 k 个顶层 h2–h4 标题配 `heads[k]`。页面写出的 id 与这里的 href
  出自同一次调用的同一个计数器。
- 每页渲染的块与页面生成器渲染的完全相同：规范、时间线、早期设计决定是 `split_head` 之后的正文；教程是
  `split_chapters` 切出的每一章的正文（教程目录页不进正文索引，它只有章节列表）。四份文档每种语言只解析一次
  （`gen/corpus`），页面与两份搜索资产用的是同一份解析结果。
- **段落**：节内按文档顺序，每个 Markdown 段落、每个列表项里的每个段落、
  每个表格行（表头行也算一行，单元格之间用 ` | ` 连接）、引用块里的每个段落各算一段。嵌在列表或引用里的
  标题算一段。代码块（含 `output` 与 `skip-check` 片段）**不进**倒排、不出摘录、**不占段号**。
  纯文本为空的单元不算段落。
- 一个词都切不出的段落（只有标点）不进 `excerpts`，不占段落编号。段落编号是全资产统一的，不是每节从 0 起：
  倒排里一个整数就指到一段，节号从 `excerpts[id][0]` 取。

### 2.3 词

`terms` 里的每个词都是对某段纯文本跑 `body_terms` 得到的；词表按码点序排（Dawn 的 `List[Char]` 比较，即
UTF-8 字节序；与 JavaScript 的 UTF-16 码元序只在 U+FFFF 以外的字符上不同）。

`body_terms(s)` 的规则：

1. 把 `s` 里每个**汉字**换成一个空格，对结果跑第一段资产的分词规则 `tokens`（刀 2 定稿，下面复述）；
2. 再按出现顺序追加 `s` 里的每个汉字，各自成为一个单字词。

汉字指 U+3400–U+4DBF、U+4E00–U+9FFF、U+F900–U+FAFF、U+20000–U+2FA1F。其他非 ASCII 的字母和数字
（`café`、`λ`、假名）仍按 `tokens` 的规则算词内字符，不拆单字。全角标点（`，`、`。`、`「」`）不是汉字，
也不是字母数字，本来就是分隔符。

`tokens(s)`（刀 2，`gen/search.dawn` 与面板共用的规则）：小写；按「不是 ASCII 字母数字、`_`、`!`、`.`、
非 ASCII 字母数字」的字符切成串；去掉串两端的 `.`；串内按 `.`、`_`、`!` 再切成片，空片丢掉；先出每一片，
串本身与唯一的片不同时再出串本身。

第一步为什么先把汉字换成空格：`inline_text` 把行内代码与正文直接拼接，中文正文里随处是 `` `Fs`效果 ``
这样的写法，拼出来是 `Fs效果`。按 `tokens` 原样切，这是一个词，`fs` 就从倒排里消失了。

一段纯文本切出的词在建倒排时去重：同一段里出现十次的词只记一次该段的编号。

### 2.4 页面怎么找到它

每页面板挂载点带上正文资产的指纹名，路径相对页面本身，与按钮上另外三个 `data-search-*` 同一写法：

```html
<div id="dawn-search" class="search-host" data-search-body="../assets/search-body-en.3f2a9c01.json" hidden></div>
```

`gen/links` 把 `data-search-body` 当作抓取的 URL 检查（存在、指纹化），并解析每份正文资产，逐条核 `sections`
里的 href：文件存在，锚点在目标页上有对应 id。

### 2.5 给刀 5 的约束（不是本刀实现，写在这里是因为它们由格式决定）

- 先读 `version`，不是 1 就不加载正文。
- 加载时把每条 posting 的差值求前缀和还原成段落编号（约 4 万个整数，一次性）。
- 查询词按同一个 `body_terms` 切。非最后一个词按全词在 `terms` 上二分，最后一个词按前缀取区间（区间内各词的
  posting 求并）；单字词（汉字）只按全词。各词的 posting 求交集得到候选段落编号。
- 查询里有连续两个以上的汉字时，候选还要做一次子串验证：在该段的 `text` 里找查询原串。`text` 是截断过的，
  所以验证不到时，若 `text` 以 `…` 结尾（截过），候选**保留但降级**（命中可能在被截掉的部分）；没截过的就丢掉。
- 结果落到节：`excerpts[id][0]` 是节号，同一节的多个命中段落合成一条结果，跳转到 `sections[sec].href`，
  摘录取命中段的 `text`。命中词可能在截掉的部分里，摘录里找不到它时不高亮，照样显示。

刀 5 照此实现，另加了四条（9.2）：一个字母的前缀按全词查；三个词以上而交集为空时退到「至少一半的词」；
标题行已命中的节不再出正文行；查询原串的验证按「每段连续汉字」逐段做，摘录里汉字之间的空格先去掉。

### 2.6 大小预算

按 gzip 计：`search-body-en.json` ≤ 120 KB，`search-body-zh.json` ≤ 150 KB（原定 90 / 130 KB；2026-10-02 两次裁决调整，
先英文到 100 KB，见 6.3，规范新增两节后两份各加 20 KB，见 6.4）。超了先议摘录长度（2.1 的 120），再议别的。`site/build.sh` 每次构建打印两份的原始字节与 gzip 字节，超预算时在 stderr 上说明。

## 四、为什么命中落在节、摘录取段落

- 能跳转的只有带 id 的标题。段落没有 id，跳到段落只能靠 Text Fragment（刀 5 可选），不能当作契约。
- 节太长，不能直接当摘录：调研量过节的中位数约 1950 字节。段落是读者扫一眼能判断「是不是这里」的单位。
- 所以倒排存段落编号，段落记着自己的节：节决定跳到哪，段落决定给读者看哪一段。段落级倒排比节级大（调研的
  Python 原型 en 46 KB 对 34 KB gz），换来的是摘录能指到命中的那一段，而不是节的第一段。

## 五、为什么中文用单字

- 中文没有空格，`tokens` 把一整段汉字切成一个词，倒排里全是只出现一次的长串，查询只能做子串扫描；
  在 wasm 里逐段 `contains` 一遍要 9–17 ms（调研 §3 的实测），每次按键都扫就超帧。
- 汉字二元组（bigram）是常见做法，但调研原型里中文 bigram 倒排有 15 316 个词、段落级 118 KB gz，比全文原样
  （116 KB gz）还大，超出预算。
- 单字倒排加候选验证：常用汉字不过两三千个，词表小；查询的每个字各取 posting 求交集，候选通常几十段，
  再对候选做一次子串验证（2.5），成本可以忽略。代价是验证只能对着截断后的摘录做，见 2.5 的降级规则。
- 不引入分词词典：生成器要在 C 后端上跑（`site-dist-diff.sh`），也没有现成的 Dawn 中文分词。

所以契约改了两处：倒排改为全资产段落编号的差值（同样的信息，en 少 22 KB、zh 少 28 KB；查询侧还少了一层
`(sec, para)` 比较，交集直接在整数上做），摘录从 240 码点缩到 120（任务单「超了先缩摘录长度」）。
调研原型估的倒排是 46 KB、摘录 44 KB，与实测的差在于原型的段落切法和截断规则与这里不同，量级估计偏乐观。

### 6.3 裁决：英文预算调为 100 KB

按原定 90 KB，英文超 9.1 KB：倒排、词表、节表三项加起来已经 58 KB，剩给摘录的只有 32 KB，约合 80 码点。
2026-10-02 主会话裁决：**英文 gzip 预算由 90 KB 调为 100 KB，中文保持 130 KB**，契约其余不变。理由：正文资产是懒加载的，
只有输入了查询的读者付这一次下载，首屏不受影响；另外两条路都改变了读者能得到的东西。

被否的两条，数字留档：

1. **摘录缩到 80 码点。** en 整份 89.0 KB gzip，进原预算；zh 108 KB。否决：80 码点约一行，读者从摘录里判断不了
   「是不是这里」，摘录就失去了作用；中文截断更多，2.5 的候选验证也会更多落到「截过、降级」。
2. **丢掉高频词**（出现在超过 10% 段落里的 53 个，`the`、`a`、`is`……）。en 倒排少约 7 KB（40.6 → 33.5 KB gzip）。
   否决：这改变了能搜到什么，含这些词的查询（短语、`is not`）在交集里失去约束，而且契约要另外列出被丢的词，
   查询侧要跟着特判。

当时：en 101 506 字节 gzip（99.1 KB，余 0.9 KB），zh 131 310 字节（128.2 KB，余 1.8 KB）。两份余量都很薄，
文档再长一些就会再超，6.4 就是这件事。构建仍只在 stderr 上报超预算，不失败。

### 6.4 裁决：预算调为 en 120 KB、zh 150 KB

刀 4 合入 main 之后，规范新增两节（构建目标、GPU 设备后端，`1a7f474b`），两份资产随之超出 6.3 的预算
（`site/build.sh` 只告警）。2026-10-02 主会话裁决：**英文 gzip 预算调为 120 KB，中文调为 150 KB**，随刀 5 一起改。
理由与 6.3 相同：正文资产懒加载，只有输入了查询的读者付这一次下载，首屏不受影响；规范长了两节，正文索引
就该大两节；缩短摘录已经在 6.3 被否过一次（80 码点读不出「是不是这里」），文档每长一点就缩一次摘录，读者得到
的东西会一路变差。

`DAWN_WASM_CC=clang-20 ./site/build.sh`，基线 `1a7f474b`：

| | 节 | 词 | posting 数 | 段落（摘录）数 | 原始字节 | gzip 字节 | 预算 |
|---|---|---|---|---|---|---|---|
| en | 153 | 4 579 | 41 763 | 1 069 | 298 811 | 107 327（104.8 KB） | 120 KB，余 15.2 KB |
| zh | 153 | 2 957 | 51 582 | 1 070 | 351 380 | 139 164（135.9 KB） | 150 KB，余 14.1 KB |

## 七、门禁

- `./bin/dawn test site`：`gen/search_body.dawn` 的测试覆盖倒排往返（抽 20 个词，posting 指向的段落确实
  含该词，摘录是该段的前缀）、差值写法、节 href 与 `render_doc` 的锚点同源、代码块不入索引、摘录在空白处截断、版本号为 1、两种语言的节表
  等长；`gen/search.dawn` 的 3.2 样例表测试。
- `scripts/site-dist-diff.sh`：正文资产是生成器产物，两条后端须同字节；生成器不得 `use java`。
- `gen/links`：`data-search-body` 存在且指纹化；正文资产的每个 href 指向写出的页面，锚点存在。
- `gen/assets` 的语言检查只扫 `.css`、`.js`、`.mjs`，JSON 不在内；正文资产里的中文不受它约束。
- `site/build.sh` 在生成之后打印两份正文资产的原始字节与 gzip 字节，并对照 2.6 的预算。

## 八、不做的（理由）

- **Pagefind。** 它在索引期切词、查询期用 `Intl.Segmenter` 切中文查询，结果用它自己的 JS UI 或 API 画；
  引入它等于把搜索的一半交给一个不在本仓、不能在 C 后端上跑的工具，并让 `site/build.sh` 依赖网络下载。
  站点的约束是生成器两条后端同字节、面板是 Dawn reactor，这两条它都满足不了。
- **JS 搜索库（MiniSearch、FlexSearch）。** 查询本身在 JS 里更快（调研实测逐段 `contains` 快约百倍），
  但面板改由 JS 画就丢了「模型携带命中」那一刀的全部收益，搜索也不再是 Dawn 写的。正文查询在 wasm 里
  每键多出约 1–6 ms（9.4），一回合的大头是标题检索以来就有的固定开销，换查询引擎省不掉它。
- **汉字 bigram。** 见第五节：比全文还大。
- **段落 id 与段落级跳转。** 渲染器不给段落发 id；为搜索给每段加 id 会让每页多出上千个属性，还要 `gen/links`
  再核一遍。跳转停在节。
- **自动纠正拼写。** 读者输入的永远原样去搜，容错只提一条建议（第十节）：自动换词会让「确实没有」与「换了个词才有」
  看起来一样，读者也就无从知道自己搜的是什么。
- **在生成器里压缩。** 预算按 gzip 计，gzip 由 nginx 的 `gzip_static`/动态压缩做；生成器没有压缩器，
  两条后端也不该各自再实现一个。gzip 字节数由 `site/build.sh` 用系统 `gzip` 量出并打印。

## 九、刀 5：查询侧（实现、出入与实测）

### 9.1 怎么进 guest、什么时候取

- **时机：输入框第一次出现非空查询时 fetch，每页至多一次。** 不选「打开面板后 idle 300 ms」：打开面板只为点一条
  最近搜索、一条推荐或者随手关掉的读者用不到正文，不该替他下载一百多 KB；而真正输入的读者，头一两个字符由标题
  回答，正文在路上。带 `?q=` 打开的页面一开就有查询，所以一开就取（读这一侧不变；`?q=` 什么时候写见第十一节）。
- **通道：重新 `init`，正文进只读 `State`，不走消息。** 消息只能经 guest 自己树里的监听器进来，而且消息的数据
  要进模型，模型每次按键都过线，等于每键来回搬三百 KB；flags 只在 init 读一次，进 `serve_with_state` 保留在
  guest 里的只读根，从不过线。刀 3 的最近搜索走的是同一条路。代价是一次 init 把两份索引都再解析一遍（9.4），
  以及重启后选中项回到第一行；输入框的文字、焦点与光标由 `search.js` 保存后放回。
- **版本：`search.js` 先 `JSON.parse` 看 `v[0] === 1`，不是就不重启；guest 的 `body_of` 再核一遍**（flags 是页面给的
  文本，guest 不信它）。没有正文时底栏写「Searches titles and API names, not body text.」/「只搜标题与 API 名，
  不搜正文。」，有了才换成「…and the documents' text」/「搜标题、API 名与文档正文。」，占位符同理。

### 9.2 与 2.5 的出入

1. **一个字母的前缀按全词查。** `s…` 覆盖几百个词、大半段落，把它们的 posting 求并是一次按键里唯一比标题检索
   还贵的一步（wasm 里约 8 ms）；只敲了一个字母的读者由标题回答，再敲一个字母正文就进来。
2. **三个词以上、交集为空时，退到「至少一半的词」。** 像 `where does the spec say handle` 这样用句子问的查询，
   没有哪一段六个词全有，严格交集答不出任何东西。这时每段按它含有的词计分，每个词的分数是 `8n/df` 的二进制位数
   （`the` 约 4、只在一段里出现的词约 13），留下至少有一半词的段，节的权重取其最高分段，只保留最高分的那几段
   给摘录挑。这一档排在所有正文行最后。中文不走这一档：单字太常见，「一半的字」说明不了什么。
3. **标题行已命中的节不再出正文行。** 规范与教程的节大多（en 153 节里 138 节）在标题索引里另有一行，href 相同；
   两行都出就是同一个地方列两遍。标题行代表它。
4. **中文验证按「查询里每段连续汉字」逐段做**（`效果 处理` 是两段，都要在摘录里找到），摘录里夹在两个汉字之间
   的空格先去掉（源文件折行留下的）。只有一个汉字的段不验证。

### 9.3 排序与分组

命中仍只存 ≤ 40 个整数；`body_base() = 1000000` 以上是正文段落号（行是它的节、摘录是这一段），一个列表保住
一个顺序，十进制偏移让转录里一眼看出 `1000412` 是第 412 段。档位（`search.dawn` 的 `answer` 头注）：

| 档 | 行 |
|---|---|
| 5..1 | 标题行，按原有 `score` |
| 0 | 某段含查询的全部词（中文另要摘录里找得到每段汉字） |
| -1 | 中文：全部字都在，但摘录截过、没能验证 |
| -2 | 9.2 第 2 条的放宽档 |

标题高于正文，是 MiniSearch 与 DocSearch 的字段加权（title > body）：标题命中就是读者要去的地方，正文命中只是
在某个地方里面。同档内按节的权重（命中段数，放宽档是最高分），再按节序。正文行进各自文档的组（spec、tutorial；
history 与 design 都进 History），范围胶囊的计数含正文行。每行：节标题（mono）、出处（`Spec › §6.5.4`、
`Tutorial › Chapter 9`、`Early decisions`）、摘录两行省略；摘录取该节命中段里词最密的一段（被截掉的词不算），
mdBook 选错段的教训。

## 十、刀 6：拼错容错（Did you mean）

依据调研报告 §3 方案 A「容错只在精确 + 前缀都为 0 命中时启用」、§6.1 刀 6、§4（rustdoc 的 `HahsMap` → `HashMap`）。
实现在 `search.dawn` 的「near misses」一节。

### 10.1 什么时候、对什么

- **触发**：`asked`（`Typed`、`Scoped` 与带 `?q=` 的 init 共用）算完 `answer` 后，**只有 `hits` 为空**（标题与已加载的正文
  都零命中；`answer` 在所选范围为空时会退回全部，所以 `hits` 空即全零）才找建议。有结果的按键一点不付。
- **词**：查询按 `terms` 切成串（与标题检索同一套）。一个词算「索引里有」：标题词（`Key.words`，只算面板画的组）或正文
  词表里有它整词；查询的最后一个词还在敲，所以有词**以它开头**也算。有的词原样保留；非 ASCII 的词（汉字、`café`）
  原样保留、不算距离；不到三个码点的词也不算（一个编辑能到的词太多，说明不了什么）。
- **候选**：缺的词在**同首字母**的桶里找距离 ≤1（词长 ≥5 时 ≤2）的词。桶 = 正文词表里以该字母开头的一段（有序表两次二分）
  + 标题词里以该字母开头的（标题词没有现成的有序表；为一个多数按键不走的分支在每次 init 排序不值，就地走一遍）。
  桶内先按长度窗口（长度差 ≤ 上限）、再按「陌生字母数」（候选里不在查询词中出现的字母，每个至少一次编辑，交换不引入新字母）
  筛掉，剩下的才算距离。候选按距离、频度（标题行数 + 正文 df）、码点序排。
- **距离**：最优串对齐距离（插入、删除、替换、**相邻交换**各算 1）。交换算 1 是因为它是最常见的手误：普通 Levenshtein
  下 `handel` 到 `handle` 是 2，与到 `hand` 一样远，四个字母的 `wiht` 也够不着 `with`。先剥公共前后缀，只算对角线
  ±上限内的格，某一行全部超限即停。
- **组合**：每个缺的词取最近的至多 3 个（手里已有 9 种组合后每词只取 1 个），与保留的词做笛卡尔积，按总距离排，
  **依次问至多 2 个**，第一个有结果的就是建议；结果数是对它跑一遍检索（标题 `matches` + 正文 `text_rows`，即范围胶囊
  的总数）真算出来的，与读者点过去后看到的总数相同。不到三个词的查询里若有词「缺且无候选」，任何组合都必然零命中
  （三个词以下没有 9.2 第 2 条的放宽档），一个都不问。

### 10.2 呈现与模型

- 无结果态第一行之后：「Did you mean `handle`? 60 results」/「你是想找 `handle`？53 条结果」（单数「1 result」）。
  建议词是**按钮**，画成链接（等宽、强调色、虚下划线，取自设计稿第三态）：它不去任何地方，而是填入输入框并查询，
  发的是 `Typed`，与最近搜索回填同一通道；输入框里按 Enter 在零命中且有建议时发 `SendMsg(Typed(fix))`。
  `search.js` 让它与范围胶囊一样在 mousedown 时不夺焦点，键盘点它后把焦点还给输入框。
- 模型多两个字段 `fix`（建议的整条查询，没有时为 `""`）与 `fix_hits`，只由写 `hits` 的那几处一起写；Escape 清空查询时一并清掉。
  encode/decode 随之；`registry.json` 原三条转录只多了这两个字段（逐字节核过：删去 `,"fix":"","fix_hits":0` 即与原文相同），
  新增第四条 `body-index-slip-did-you-mean-click-enter-session`（`handel` → 建议 `handle` → 点按钮 → 有结果；`amrs` → Enter → `arms`）。
- 不做：自动纠正（见第八节）；汉字的编辑距离（单字本来就能命中）；`?q=` 不变（「复制链接」写进地址的是输入框里读者自己的查询，不是建议，第十一节）；首字母错的拼写
  （见 10.4）。

| zh | `efect` | 6.1 / 6.4 / 6.4 | 2.4 / 2.6 / 2.6 | 6.1 / 13.5 / 17.3 | 4.7 / 13.2 / 18.4 | effect，44 |

容错分支本身（有容错减无容错的末键）：四个点名查询中位多 1.5–5.3 ms，最坏的 `sturct strnig zzzzzz` 多约 11 ms，
整个末键最坏 14.3 ms，在 15 ms 内。分步（同一份 `search.dawn` 编成独立 wasm 在 Node 里量，`suggest` 整步，20 次取差）：
`handel` 3.8、`efect` 4.1、`hahsmap` 1.3、`wiht handel` 5.0、`sturct` 4.8、`sturct strnig zzzzzz` 10.1 ms；其中一次重查约 2–2.5 ms，
一个桶（走标题词 + 正文一段 + 筛 + 算距离）约 1.1–2.7 ms。「全部按键」一栏两边的最大值都来自中途有结果的前缀，与容错无关。

一路削下来的三步（同一 Node 分步法）：

1. 桶里先按长度窗口筛再进映射：标题词里 `string` 之类在几百个签名里重复出现，原先每次都是一次映射写入。
2. 距离剥公共前后缀、只算对角带：每次距离 12.7 µs → 约 3 µs（`sturct`/`struct` 只剩 `ur`/`ru`）。
3. 「陌生字母」筛：`sturct` 的桶求候选 5.5 → 2.5 ms，大多数词连表都不用画。

再加上「问至多 2 个组合」和「两词以内有死词就不问」，把最坏的三连拼错的末键从中位 21.9 ms（问 3 个、无陌生字母筛时的浏览器实测）压到 13.2 ms。

体积：`tea-search.wasm` 691 910 → 715 587 B（gzip 203 375 → 209 281）；`search.js` gzip 6 747 → 6 829 B。init 没有新增工作。

### 10.4 取舍与出入

1. **首字母不容错。** 首字母分桶是有损的：`andle` 找不到 `handle`。要无损就得对全部词算距离，即调研量过的 12.5 ms；
   首字母也是读者最不容易打错的一个。Elasticsearch 的模糊查询有同一个旋钮（`prefix_length`）。测试
   `the first-letter bucket misses no word that a walk of the whole index finds` 钉的是「同首字母范围内」不漏：
   对每个样例词，桶的答案与把整张词表（标题词 ∪ 正文词）逐个量一遍再限同首字母的答案相同，样例落在有序表的两端（`a`、`w`）与中间。
2. **距离用相邻交换算 1 的最优串对齐**，不是任务单字面的「编辑距离」（Levenshtein）。理由见 10.1。
3. **不到三个码点的词不纠**，任务单没写；一两个字母的词在一次编辑内能到几十个词。
4. **只问至多 2 个组合**，见 10.3；第三个往后的组合（两个缺词各自的次近词）不再尝试。

## 十一、`?q=` 只在「复制链接」时写

刀 3 起，面板开着时地址栏跟随输入框（每次输入 `replaceState` 一次 `?q=`），关面板时清掉。改为：

- **读不变。** 带 `?q=` 打开的页面仍直接展开，查询经 flags 进 guest，init 第一轮就答。
- **写只在读者要链接时。** 底栏在输入框非空（`trim` 后）时多一个「Copy link / 复制链接」按钮。点它，
  `search.js` 把当前查询 `replaceState` 进地址，再 `navigator.clipboard.writeText(location.href)`；
  剪贴板不在或拒绝（无权限、非安全来源）时，地址放进面板下方一个只读输入框并选中，由读者自己复制，不弹 alert。
  输入不再写地址；关面板仍清掉 `?q=`，所以复制过再关，地址回到干净的。
- **为什么。** 地址随每个按键变，等于替读者造了一串他没要的链接：读者自己从地址栏复制时拿到的是敲到一半的前缀，
  而真正要分享的那一刻并没有一个动作。现在链接只在读者明确要它时出现，地址栏里的就是剪贴板里的那一条。
  代价：复制后再改查询，地址仍停在复制时的那条，直到关面板（输入时不写地址是本节的前提，这一条不另外处理）。
- **按钮不带监听器。** 与删除、清空一样，按钮只带 `data-copy-link`，由 `search.js` 在挂载点上委托处理：地址与剪贴板
  都是页面的，guest 够不着。
- **「已复制」的反馈走页面的状态类，不走 guest 的消息。** guest 把两种文案（「Copy link」「Copied」/「复制链接」「已复制」）
  与一条 `role="status"` 的提示（「Link copied」/「链接已复制」，视觉上隐藏）都按页面语言画好；`search.js` 在剪贴板确认之后
  给挂载点加 `is-copied`（与 `is-keying` 同一做法），样式表据此显示「已复制」与那条提示，1.6 s 后撤掉；下一次输入或关面板也撤掉。
  不选「guest 用一条消息翻状态」：消息只能经 guest 自己树里的监听器进来，页面 dispatch 不进去；若给按钮挂监听器，
  guest 会在剪贴板答复之前就宣布「已复制」，拒绝时也一样；guest 也没有时钟把这句话收回。页面脚本自己不带任何文字
  （`gen/assets.dawn` 的规矩），兜底输入框的可访问名由按钮的 id 借来（`aria-labelledby`）。
- 按钮在 mousedown 时不夺焦点（与范围胶囊、建议词同一处理），点完焦点仍在输入框，方向键与 Enter 照常。
- 测试：guest 的 `the foot offers copy link only while there is a query`（空与全空白时没有、非空时有一个、无监听器、
  两种语言的文案）；`flags carry a shared query …` 管读这一侧，不变。
