# JVM 操作数中的循环跳转

> 状态：**current**。issue #80 已实现；下文记录动码前方案及验证边界。

`out = out ++ [if … { continue } else if … { break } else { h }]`
在 JVM 发射时进入 ASM 帧合并失败；native 可以执行。已有 #68 修复属于
native 临时引用的退出清理，不能用它代替 JVM 操作数栈的证明。

JVM 的调用、构造器、列表与二元算术通常先把前面的操作数压栈，再求后面的。
后面的表达式若跳到循环标签，先前的值也到达该标签，而正常循环路径没有它们。
仅在列表拼接处补一条 pop 不够：接收者、宽数值、嵌套构造器都可占栈，目标还
可能是外层循环。也不让通用 Core 或 native 为 JVM 的机器栈改变形状。

在 JVM 方法发射前做局部准备：同一次底向上遍历收集表达式可能跳出的循环 ID，
循环节点移除自己的 ID，分支保留分支结构。有逃逸操作数的运算按原求值顺序
把操作数放到局部变量，再发射原运算；这样 NEW、接收者和早先参数都不跨越
可逃逸的求值。没有逃逸的子树维持原形；短路右边与条件分支绝不提前求值。
临时符号从已用符号之后分配，宽度继续由既有 JVM 类型表示决定。
选择局部准备而非只改参数 helper，是因为后者看不到调用者已经压栈的接收者和
NEW/DUP；逐跳转 pop 则必须重新追踪整套机器临时栈。Java 参数另沿原有转换
helper 逐个转换后暂存，接收者和变长数组也用局部保存；不是先求完所有原始
参数再转换。SAM 隐藏快照由 checker 的 evidence_pack 构造，只有环境读取与
纯证据结构，没有用户 break/continue；转换时机保持原位。
独立复审推翻了 Java 构造器可以把 NEW 延后的初版实现：NEW 触发类初始化，
可观察的初始化副作用必须先于参数。修正保留原位 NEW，把未初始化引用存入
局部变量，参数完成后再加载、DUP、调用构造器；真正 continue／break 的路径
丢弃该局部而不携带操作数。外部 Java 初始化器与延后 NEW 的独立变异固定时序，
JVM 验证器同时检查回边上的未初始化状态。

验证覆盖原报告、非空初值、break 与 continue、宽整数与浮点、普通和动态调用、
构造器、嵌套循环及副作用顺序；原父编译器必须在同一回归上精确出现 ASM 帧异常。
JVM/native 对拍与 ASan/LSan 同跑，并保持 #78 的 RC 语料通过。运行官方 Core
重录／检查、固定点与类文件门禁；与真实父编译器逐份比较 emit 语料后再逐字声明
对应的 `Emit-Change`，不借已有声明掩盖未经测量的差异。

首轮实现验证：整合已验收修复链后 603 项编译器测试通过；新循环操作数与
#78 的 RC 操作数退出语料均通过 JVM/native 对拍及 ASan/LSan。原父提交
`5c6c3171` 的编译器对原始报告精确报 ArrayIndexOutOfBoundsException，栈顶是
ASM Frame.merge；门禁另分别关闭 Core 暂存与 Java 暂存，要求同一异常而非
任意编译失败。可变局部快照另放 JVM 语料：原 native 在无循环跳转的
调用里也会晚读第一个参数：初值 2 的局部先作第一实参，第二实参递增它后返回 1，
十进制组合应得 21，原 native 却得 31。这属于独立问题，
不在本次 JVM 修复里改变它。

不做的：不改变语法、控制语义、native RC，不关闭 ASM 帧计算或放宽验证器，
不把所有普通操作数统一改写成局部变量。
