# 控制运行时与效果证据的可达性裁剪

> 状态：**current**。issue #71 的动码前方案；验证结果随实现回填。

`std/io` 声明 `ctl effect Exit` 之后，声明扫描让所有程序都携带三份控制运行时
类，模块 ADT 发射同时保留了未使用的效果证据。`chars.dawn` 无需这些类。
issue 初稿把 `examples/effects/handlers.dawn` 列为保留三个控制类的正例，但它只有
普通 `effect Env`，并不暂停。验收以实际控制处理器语料
`scripts/spike-native/ctl_resume.dawn` 为正例；普通处理器保留 `Env` 证据并继续
运行，控制运行时可以移除。

扩展 `ir/reach` 已有的同一次工作队列遍历：可达 `ctl_run`、`ctl_yield` 标记
控制运行时；可达函数的签名、隐藏证据参数和 Core 类型位置记录 ADT 引用。
函数类型中的效果标签也记录相同 ID 的证据类型，动态调用保持保守。
总会发射的普通 ADT 字段与 trait 接口方法 ABI 同样提供类型根：它们即使没有
调用者也必须能解析描述符。Java 静态调用还显式提供 owner 与描述符类型，
不能只看返回值。Java 类依赖只追随实际描述符位置；`List[Ctl]` 与 `fn(Ctl)`
的子类型会擦除，不能因递归类型扫描而误留运行时。
JVM 主驱动在得到结果后决定是否生成三个控制类；模块发射只对名称由编译器
保留的 `ev$` 记录使用 ADT 可达性过滤，普通 ADT 不改变。

无目标的运行时 JAR 与完整标准库测试继续使用 `None`，保留全部类。
`CtlDiscard` 仍保留：无条件生成的 IO 运行时中 `bracket` 与屏障引用它，
移除它需要先裁剪这些运行时成员，超出本次已有 std 可达性裁剪的边界。

验证以父提交编译器为基准：`chars.dawn` 只减少不必要类，共有文件逐字节不变；
声明但不使用的效果不增加运行时，动态签名、操作、处理器和跨模块调用保留所需
证据。类文件门禁的声明耦合断言改为程序可达性断言，并用关闭裁剪和过度裁剪的
负控证明两侧有效。运行编译器测试、自举固定点、类文件验证、双后端语料、正式
Core 重录和检查；逐条测量差分后声明对应 `Emit-Change`。

独立类文件检查复用常量池解析，但单独读取字段、方法声明描述符及 MethodType。
只有普通字符串提到类名不构成依赖；描述符单独提到类名却不能遗漏。这两个方向
由独立 Java 夹具和缺失／多余运行时变异体固定。

不做的：不扩大普通 ADT 的裁剪范围，不改变控制语义或 JDK export 配置，不为
运行时另开一遍函数可达性遍历，也不在 C 后端改变已有的内存管理或控制运行时。
