# 内页「Horizon」：全站暗色、短天空带与阅读排版

> 状态：**current**。2026-10-02 由内页定稿（11 页单文件稿，说明见 agent-handoff 的
> `inner-pages-note-20261002.md`）落到 `site/`；本文动码前写成方案，落地后按实测回填了第九节。
> 首页的设计在 [site-home-design.md](site-home-design.md)，本文只讲首页以外的 107 个页面，
> 以及两者共用的那一层（token、字体、主题脚本、导航、页脚）。

## 一、问题

首页（v0.82.0）有了一片天、亮暗两套主题和一组克制的动效，其余页面还是旧样子：只有亮色，
页头是一条白底导航，标题在正文里，可运行的代码块下面挂一条链接，表格是撑宽的 `display: block`。
定稿把内页做成「首页那片天缩成一条短带」：带里是导航和页头（eyebrow、标题、导语、译本说明），
带的底边是首页那条 3px 拂晓渐变线，线下面是普通的阅读页。

落地要守的纪律与首页相同：站点零外部请求；JVM 与 native 两个生成器写出逐字节相同的
`site/dist`；对外文案英文是正本；页上每个数字有生产者。另外两条是这一批特有的：

1. **一份 token、一份主题脚本。** 首页的 token 原本只在 `home.css`，主题脚本只在 `home.js`。
   内页不能复制第二份，否则两边各改各的。
2. **正文文字不变。** 除首页外，每页去掉标签后的正文与 v0.82.0 产物一致；差异只允许是
   定稿说明里列出的两处（教程目录章号补零、示例描述的反引号渲染成代码），外加本批修的
   删除线 bug（`~~` 不再原样显示）。

## 二、壳子

每个内页自上而下：

```
<div class="progress">              顶部 3px 进度线（animation-timeline: scroll()；不支持时是满宽渐变线）
<header class="sky">                短天空带
  <svg class="stars">               7 颗淡星，只在暗色下可见
  <div class="glow">                地平线上方的低光
  <div class="wrap">
    <nav class="site-nav">          品牌、.links（栏目、中英胶囊、搜索、GitHub）、日月按钮
    <div class="page-head">         eyebrow、h1、lede、译本说明（.twin）
<div id="dawn-search">              搜索面板挂载点（刀 1）
<main class="wrap page">            正文：单栏 .col.prose，或 .with-toc（目录栏 + article.prose）
<footer class="site-footer">        logo、文案、右侧等宽版本号
```

- **导航只有一份标记**：`html/page.nav_bar` 首页和内页都用。日月按钮从 `.links` 里挪到 nav
  末尾（这是定稿与首页旧标记唯一的差别），手机宽度下用 `order` 把它排到第一行，与品牌同行，
  栏目换到第二行。首页随之换成同一份 nav，`home.css` 里那套 `.sky .site-header` 规则删掉。
- **页头数据由各 `gen_*` 给**，壳子不猜。`html/page.PageHead` 是一个记录：eyebrow、标题、
  导语、译本说明都是已经转义好的标记，外加一个版式类（`col` 单栏对齐、`toc-aligned` 与正文栏
  对齐、`nf` 404 居中）。没有页头的页面（Playground）传空记录，壳子就不输出 `.page-head`。
- **h1 与译本说明从正文抽到页头**：`html/render.split_head` 从块序列里取出第一个 `#` 标题和
  紧随其后、整段只是一个 `*…*` 的段落（译本说明），其余照常渲染。抽取规则写在渲染器里，
  不靠生成后的 HTML 正则。
- **eyebrow 只写页面里已有的事实**：

  | 页 | 英文 | 中文 |
  |---|---|---|
  | 教程目录 | `tutorial · 17 chapters` | `教程 · 共十七章` |
  | 教程章节 | `tutorial · chapter 8 of 17` | `教程 · 第八章，共十七章` |
  | 规范 | `specification · normative · 0.82.0` | `规范 · 权威 · 0.82.0` |
  | 时间线 | `history · timeline, first commit to today` | `历史 · 时间线，从第一个提交到今天` |
  | 早期决定 | `history · decisions of M0–M7 · historical` | `历史 · M0–M7 的决策记录 · 历史文档` |
  | 标准库 | `stdlib · generated by dawn doc --stdlib` | `标准库 · 由 dawn doc --stdlib 生成` |
  | 示例目录 | `examples · run by CI, byte for byte` | `示例 · CI 逐字节核对` |
  | 单个示例 | `examples · <分类名>` | `示例 · <分类名>` |
  | 演示 | `demo · two wasm reactors` | `演示 · 两个 wasm reactor` |
  | 404 | `404` | （404 只有一页） |

  章数由教程的 `##` 切分数出；规范的版本取构建环境的 `DAWN_SITE_VERSION`（`site/build.sh`
  从 `selfhost/src/version.dawn` 读），为空时 eyebrow 不写版本，不写死。

- **logo**：导航与页脚都用同一个 `<img src=logo.svg>`，不内联 SVG。见第八节。

## 三、暗色 token 全站化

- `style.css` 的 `:root` 放亮色 token，暗色写两处：`@media (prefers-color-scheme: dark)` 下的
  `:root:not([data-theme="light"])`，以及 `:root[data-theme="dark"]`。三态与首页相同：根元素
  没有 `data-theme` 时跟系统，有则覆盖系统。
- 主名是首页那套（`--bg`、`--surface`、`--text`、`--muted`、`--faint`、`--line`、`--line-soft`、
  `--accent`、`--code-bg`、`--out-bg`、代码配色 `--k/--t/--f/--s/--n/--c`、`--hue-1/2/3`、
  天空 `--sky-*` 与 `--night-op`、`--star-op`）。旧名 `--border`、`--border-soft`、
  `--output-bg`、`--code-bg-soft` 留作别名，因为 Playground 的 `playground.css` 读它们。
- `home.css` 删掉重复的 token 块，只留首页专有的：`--phase`（日月轨道）、跟着 `data-sky`
  走的首屏色（`--h-*` 与首页自己的 `--sky-*`），以及首页各节的规则。
- JetBrains Mono 的 `@font-face` 从 `home.css` 挪到 `style.css`：全站的 `--mono` 都是它。
  生成器改写的 `url(...)` 随之改到 `style.css` 上；首页仍然 `preload` Regular。
- 搜索面板（刀 1）已经只读 token，自动跟随；它写死的阴影色走 `light-dark()`，读的是
  `color-scheme`，`style.css` 的暗色块里设 `color-scheme: dark`。
- 演示页里 guest 画的按钮和输入框原来写死 `#fff`，改用 token。
- Playground：只改 `site/play-ui/src/playground.css` 的变量映射（不动 TS）。编辑器外壳
  （侧栏、工具栏、输出面板）跟 token 走；**编辑区本身保持亮色**，因为语法高亮的颜色写死在
  `dawn-lang.ts` 的 `HighlightStyle.define` 里，CodeMirror 生成的类名不稳定，CSS 变量覆盖不了，
  暗底上 `#0a3069` 的字符串色看不见。见第八节。
  （后续：issue #342 已把编辑区也接上主题，见第八节该条下的补记。）

## 四、主题脚本与切换

- `home.js` 拆成两个文件：**`theme.js`**（全站）与 **`home.js`**（首页专有）。两个都放在
  `<head>` 里、不加 `defer`，`theme.js` 在前：第一件事是在首帧之前把上次选的主题写到
  `<html>` 上，否则先闪系统主题。localStorage 键沿用 `dawn-theme`，读写都包 try/catch。
- `theme.js` 管：恢复主题、按钮的 `aria-label` / `aria-pressed`、写 localStorage、点击切换、
  窄屏折叠目录（原来 `page_with_toc` 后面那段内联脚本并进来；断点随 CSS 改为 959px）。
  按钮在标记里是 `hidden`，脚本运行后才显示，没有脚本它什么也做不了。
- **内页的切换用 view transition 圆形展开**：新主题从日月按钮处以圆展开，560 ms。任一时刻
  每个像素要么是旧主题要么是新主题，不会有深浅两种墨色在半黑的天上交叉的那一段灰压灰，
  也不会撞上 Chrome「父元素颜色在过渡时，子元素自己的颜色过渡每帧重启」的问题（定稿说明记过：
  带里的 h1 在 600 ms 里颜色一直没变）。不支持 view transition 的浏览器、以及 reduced motion
  下，主题直接切换。
- **首页保留日月轮转**。`home.js` 向 `theme.js` 登记一个切换函数（`window.dawnTheme.turn`），
  首页点按钮时走它：`data-theme` 立即翻转，`data-sky` 在 420 ms 时翻转，轨道转半圈，代码「暗一下」。
  首页地平线以下不改用 view transition，理由：view transition 期间旧状态是一张静止的快照，
  首页的轨道 1.4 s、夜色淡入 1.2 s 都比 560 ms 的圆长，圆展开完以后这些动画要么被截在快照里、
  要么在圆外看不见；而且首页的编排（`data-sky` 滞后、代码暗一下）本身就是为了解决同一个灰压灰
  问题实测出来的。两种手感分属两种页面：首页的切换是一段演出，内页的切换是一次换色。
- **首页地平线以下的过渡只挂在自己设了该属性的元素上，且只过渡那个属性**（`home.css`，与首屏那份列表同一原则）。
  原来是一条 `:root.theme-anim .band *, footer *`，给每个元素挂五条过渡：过渡在计算值变化时就会启动，继承来的也算，
  所以只是继承颜色的子元素在父元素过渡的每一帧都重启一次自己的过渡，而它若不挂过渡，本来就会逐帧跟着父元素走。
  现在按属性分成互不重叠的几张表：只设颜色的（标题、正文段、链接、标签文字……）、只设底色与边框的（`.band`、卡片、
  胶囊、分隔线）、两者都设的（页脚、行内代码、图标块、`.tags li`），以及双后端示意图的 `fill`/`stroke`。
  `body` 只过渡底色不过渡颜色：`body` 上的颜色过渡让它下面整棵树每帧重算样式（首屏也在里面），是列表化以后剩下的
  大头；从 `body` 继承墨色的只有各节的 `h2`/`h3` 与数字块的 `strong`，它们单独列出。地平线以下的代码窗
  （代码块、窗框、标题栏、输出条）一律不过渡，点击当帧整块换色：token 的颜色不能过渡（首屏代码「暗一下」的理由），
  底色过渡而字直接切会让一帧里出现新主题的字压在旧主题的底上；首屏的「暗一下」搬不下来，因为它掩盖的是 420 ms 后
  随 `data-sky` 来的换色，而地平线以下的颜色在点击当帧就变，暗一下只能从谷底开始，那就是直接切。伪元素与
  `box-shadow` 原来就不在 `*` 里，仍是直接切；`color-mix()` 派生的颜色都落在已列出的元素自己的属性上，随变量
  一起过渡。逐元素核对（亮、暗各取一次计算值，凡是变了的颜色、底色、可见边框、`fill`/`stroke`，要么自己过渡、
  要么从过渡的祖先继承）的结果：代码窗以外没有直接切的。
  实测（playwright-core 1.63 / Chromium，1440×900，本机 `python3 -m http.server` 伺服 `site/build.sh` 的产出，
  点一次按钮后记 1.7 s 的帧间隔，4 倍 CPU 降速，每组 8 次交错跑、取中位数；本机当时负载约 4）：

  | | 帧数 | 最长一帧 | 点击后首帧的过渡 | 样式重算（合计） |
  |---|---|---|---|---|
  | 改前（`.band *`） | 60 | 133 ms | 677 条 / 445 个元素 | 约 850 ms |
  | 任务单的参照：只去掉 `.band *`、`footer *` | 90 | 50 ms | | |
  | 改后（按属性的列表） | 90 | 50 ms | 284 条 / 184 个元素 | 约 440 ms |
  | 下限：所有过渡都去掉 | 102 | 33 ms | | |

  不降速时改前 100 帧、最长 33 ms，改后 103 帧、17 ms。任务单在线上页、另一台机器上测的同一参照是 98 帧、50 ms，
  改前 63 帧、117 ms；本机比它慢一截，改后与参照持平。剩下的差距全在颜色过渡（只去掉颜色、保留底色与边框时 95–100 帧）：
  文字换墨色每帧都要重算样式、重绘字形，这是「地平线以下也渐变」本身的价钱，不是列表能再省的。
- 按钮的两种文案由生成器按页面语言写进 `data-label-dark` / `data-label-light`（任务单写的是
  `data-to-dark` / `data-to-light`；首页已上线的就是 `data-label-*`，全站用一个名字，沿用它），脚本里不含
  任何文字（`gen/assets.dawn` 不许共享脚本里出现中文）。文案只定义一次：`html/page.theme_toggle`，
  首页也用它，首页文案文件里原来那两节删掉。

## 五、Markdown 渲染（`html/render.dawn`）

- **节号**：带 id 的 h2–h4 若以节号开头（`1.`、`2.1`、`9.8.1`、`D3`、`M5`，后跟空格），
  节号拆成 `<span class="hn">`，标题末尾加 `<a class="anchor" href="#id" aria-hidden="true" tabindex="-1">#</a>`。
  `gen/links.dawn` 的节号核对原来读「标题里第一个标签之前的文字」，节号拆进 span 以后它会读到空串、
  静默跳过全部核对；所以它改成先认 `span.hn`，并且构建日志里的「numbered heading」计数必须与改前相同。
- **表格**外包 `<div class="table-wrap">`，窄屏在容器里横向滚动，不撑宽页面。
- **状态框**：正文（抽掉标题和译本说明之后）的第一个块若是引用，加 `class="status"`。
  只认第一个块，所以教程章节里正文中间的引用不受影响。
- **删除线**：`~~…~~` 渲染成 `<del>`（新的行内节点）。现站设计史「非目标」表里四处 `~~` 原样显示，是 bug。
- **时间线列表**：一个顶层无序列表，若每一项都以粗体开头、且粗体文字以里程碑号（`M` 加数字）
  或日期（四位数字加 `-`）开头，加 `class="timeline"`。这按结构认，不按位置（定稿是「`id="s5"`
  之后的第一个 ul」，节一挪就错）也不按标题文字（中英两份标题不同）。命中的是早期决定的
  「里程碑」与时间线文档的各期列表，构建后核对命中数。
- **可运行代码窗**（`html/play.dawn`）：`.playable` 改成 `figure.win.playable`：顶栏是三个圆点、
  标签（教程里是 `dawn`，示例里是文件名）、右侧「Open in playground」链接；然后是代码；
  若代码块后面紧跟一个 `output` 围栏，它被收进同一个窗口。配对在渲染器的块循环里做
  （列表项、引用里的块走同一个循环）。

## 六、各页

- **教程目录**：导语移进天空带，原来的 `<hr>` 不再输出；章节列表是一条「路」：
  `ol.chapters`，每章 `li` 带序数 `--p`（0 到 1，三位小数），编号圆片里是补零的章号，颜色按 `--p`
  从靛蓝插值到品红（`color-mix`），一条竖线贯穿圆片；悬停整行浅底、右侧滑出箭头。
- **教程章节**：左栏是全部章节的目录（当前章高亮、`aria-current="page"`），上一章 / 下一章是两张卡片，
  各带一个等宽小标签（`← previous` / `next →`，中文 `← 上一章` / `下一章 →`）。第一章的
  「上一章」卡片指回目录。
- **规范、早期决定、时间线**：`page_with_toc`；目录里的节号拆成等宽灰字。
- **标准库**：结构不动，第一段导语移进天空带；签名换行（`pre-wrap` 加悬挂缩进）、分组名 sticky、
  被链接条目的左边线、impls 虚线框、参考 kernel 折叠卡片都由 CSS 完成。
- **示例目录**：每个分类一个色点（三色轮换）和一个数量胶囊（数字按该分类实际列出的条目数算）；
  条目两栏：左边名字，右边描述；描述里的反引号渲染成 `<code>`。
- **单个示例**：每个运行案例是一个终端窗（`$` 提示符、stdin、stdout、stderr 都在窗里），
  源码窗顶栏标文件名；单文件示例的源码窗带 Playground 链接。分类名进 eyebrow。
- **演示**：第一段移进天空带；两个挂载框外包窗口（`#tea-counter · wasm reactor` /
  `#tea-todo · wasm reactor`）。挂载点 id、`data-wasm`、`Loading the demo…` 状态行、两段脚本都不变；
  **不画静态首帧**，框里是真实 wasm 加载出来的东西。
- **Playground**：天空带里只有导航，不输出页头。
- **404**：页头居中；带底一轮太阳只露出顶边，压在地平线下。

## 八、不做的（理由）

- **内联 SVG logo 与两个 gradient id。** 任务单要求导航与页脚各内联一份 logo SVG、用不同的
  渐变 id。没有照办：首页设计（[site-home-design.md](site-home-design.md) 第八节）已经裁过
  「用同一个 `<img class="brand-logo">`：同一文件、已被缓存，也免去为避免重复 id 而改的两个渐变 id」；
  内联只在要按主题给 logo 换色时才有理由，而这一版 logo 两种主题下都是同一套渐变。
  页脚的 logo 同样用 `<img>`。
- **静态首帧。** 定稿在演示页的两个挂载框里画了按源码推出来的首帧。不做：那不是 wasm 跑出来的，
  而且 bridge 拥有挂载点里的一切，watchdog 也把「挂载点为空」读作「还没挂上」。
- **Playground 编辑区暗色。** 高亮色写死在 TS 里，本批不动 TS。编辑区保持亮色，外壳跟主题。
  另开 issue：把 `dawn-lang.ts` 的 `HighlightStyle` 改成读 CSS 变量（或用 `tags` 到类名的
  `classHighlighter`，颜色交给 CSS）。
  补记（issue #342，2026-10-02）：已做。`dawn-lang.ts` 改用 `tagHighlighter` 输出稳定的
  `tok-*` 类（关键字、类型、定义名、字符串、插值、数字、注释，外加一个不上色的
  `tok-variableName`，让普通标识符仍各占一个 span，亮色下文字分段与原来一致），颜色在
  `playground.css` 里读 `--k/--t/--f/--s/--n/--c`；`.dp-editor` 的亮色钉子删掉，编辑区亮色仍是
  `#fff`，暗色是 `--code-bg`。CodeMirror 自带基础主题只有亮色值生效（从没告诉它「现在是暗色」，
  站点主题是三态、在 CSS 里），所以光标、tooltip、补全选中项、lint 活动区间、error lens 这几处
  用 `light-dark()` 重写：第一个值就是原来的亮色值，第二个值取站点 token。亮色下三张截图
  （初始、补全弹窗、全选）与改动前逐像素相同；暗色下六种 token 色对 `#161b22` 的对比度
  5.62–11.25（注释最低），正文 14.64。
- **代码块不换行。** 规范在 1280 px 下仍有约四分之一的代码块需要横向滚动。让代码换行会伤语法块的
  可读性，与定稿结论相同。标准库签名例外：它们都只有一行，换行后悬挂缩进。
- **Google Fonts。** 与首页相同，字体自托管。
- **首页地平线以下改用 view transition。** 见第四节。
- **中文规范、标准库的长页单独调排版。** 定稿只做了中文教程目录；中文长页沿用同一套规则，
  66ch 约等于 33 个汉字一行。

## 九、实测

环境：playwright-core 1.63 / Chromium，本机 `python3 -m http.server` 伺服 `DAWN_WASM_CC=clang-20 ./site/build.sh`
产出的 `site/dist`（含真实 wasm 与 Playground bundle）。12 个页面：教程目录、第 8 章、规范、示例目录、
shapes、标准库、时间线、早期决定、Playground、演示、404、中文教程目录。

- **宽度**：1280 / 400 px × 亮 / 暗共 48 组，`scrollTo(99999, 0)` 后 `scrollX` 全为 0，代码块、表格、
  目录、SVG 以外没有元素越出视口。`documentElement.scrollWidth` 是 1265 / 385，`clientWidth` 是
  1280 / 400：差的 15 px 是 `scrollbar-gutter: stable` 在覆盖式滚动条下留的槽，与定稿实测相同，
  不是溢出。
- **reduced motion**：48 组 `document.getAnimations()` 都是 0；开脚本点按钮后仍是 0。Playground
  页点按钮后曾是 6，来源是 `playground.css` 里两个按钮无条件的颜色过渡，已挪进
  `prefers-reduced-motion: no-preference`。首页（日月轮转那套）在 reduced motion 下点按钮前后也都是 0。
- **无脚本**（加 reduced motion，400 px）：12 页动画都是 0；有目录的 5 页目录全部展开、条目全可见
  （规范 75 条、第 8 章 17 条）；正文与页头里没有不透明度为 0 的元素；日月按钮不显示。
- **主题切换**：12 页点一次后 `data-theme=dark`、localStorage `dark`、背景 `rgb(15, 17, 23)`、
  `aria-label` 变为 Switch to light theme（中文页「切换到浅色主题」）、`aria-pressed=true`；刷新后仍暗；
  再点回到亮色。
- **History**：`/history.html`、`/design.html` 及两个中文版都 200；时间线链到 `design.html`，
  早期决定的 eyebrow 与状态横幅链回 `history.html`。
- **演示页**：两个 reactor 真实挂载（计数器点 + 后为 1），状态行与错误行为空，挂载点在窗口里，亮暗都无页面错误。
- **节号核对**：构建日志的「numbered heading id」仍是 166，与改动前相同（`gen/links` 读进了 `span.hn`）。
- **正文一致性**：与改动前（基线 `18eb46bc` 的构建，v0.82.0 加搜索面板刀 1）逐页比去标签后的正文，
  107 页里 21 页完全相同；56 页只差 Playground 链接从代码下方挪到窗口顶栏（文字位置变了）；
  28 页差在反引号渲染成代码、`~~` 渲染成删除线、示例目录去掉了名字与描述之间的「—」（两栏以后它不再是分隔）；
  剩下 2 页是中英教程目录：章号补零（`1.` → `01`），以及译本说明排到导语之后（定稿的页头顺序）。
  比较时去掉了新增的界面：eyebrow、`#` 锚点、窗口标签、数量胶囊、章节卡片的方向标签与箭头、目录栏。
- **首页**：亮暗、1280 / 400 整页截图与改动前对比，只有页脚换成新版式（logo、文案、右侧版本号）。

没有测的：Safari、Firefox（view transition 不支持时走直接切换这条路径没实测）；960 px 与 720 px 两个断点
附近的截图；标准库长页上 view transition 的帧率。
