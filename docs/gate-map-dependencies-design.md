# 示例依赖的门禁归属

> 状态：**current** —— issue #63 的闭包归属规则与负控。

issue #63 的修复方案：示例门禁已经从目录发现程序，但 gate-map 的路径解析止于示例目录，遗漏 `dawn.toml` 指向的包。`gpu_fake` 依赖的 tileir 改了参数类型，地图因此没有提示运行能发现调用点不匹配的两个示例门禁。

复用地图已有的仓内项目闭包解析，沿示例 manifest 的字符串依赖递归读取 manifest 与 src。只把已经 coarse 覆盖示例 manifest、且脚本仍保留实际编译调用的两个示例门禁传播给其依赖；不登记包名到门禁的手写表。格式化或文档检查只读文件，不借此获得依赖归属。闭包解析失败时报告具体示例及原因，不传播半份闭包。

验收同时覆盖新增示例、直接依赖、传递依赖与移除依赖；新增规则失效时测试必须拒绝，不能以其他门禁恰好覆盖同一路径代替。历史 fixture 仍从自己的 Tree 读取依赖。

不做：抓取外部依赖、猜测 URL 对应哪个本地包，以及把包的文档或独立测试归给只编译它的示例门禁；本规则只归属实际项目输入（manifest 与 src）。#58 的性能调查另按实测结论处理。
