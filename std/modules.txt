# Bundled std modules, in dependency order (spec §10.6). Each name is a
# resource std/<name>.dawn, importable as `use std/<name>`; the file's name is
# the qualification alias (map.insert, str.trim, ...).
cursor
str
# char before fmt and bytes: both scan ASCII digits, and reading a character
# as its code point is `char.code`, so the module has to be checked first.
# Its own tests therefore stop at std/str -- the "a character can be a Map
# key" claim lives in std/map's tests, which are checked after both.
char
fmt
# loc reads a site's line and column with fmt.parse_int
loc
# dtype is the device-format type that the witnesses in the modules after it
# are written in. It imports nothing and sits under every module that declares
# a format.
dtype
# narrow depends on nothing but the builtins; it sits here so the modules
# below may use it. gpu does: the bf16 rounding and bit codec.
narrow
# The fixed-width integers depend on nothing but the builtins and dtype, and
# nothing in std uses them; each is its own module so that `u32.wrap` and
# `u8.wrap` are the same name qualified differently (std/int/u32's header says
# why). They sit under int/ so that seven of them do not crowd the top level;
# `use` binds a path's last segment, so `use std/int/u32` still qualifies as
# `u32`.
int/i8
int/i16
int/i32
int/u8
int/u16
int/u32
int/u64
# float holds the two Float values no literal spells; it depends on nothing and
# nothing in std uses it.
float
# list precedes bytes: `for` desugars through the prelude Iter trait, and
# bytes' own for-loops need the `impl Iter[List[T]]` std/list registers
list
bytes
io
# The reactor pump owns a process/module-lifetime root through internal io
# runtime primitives. It depends only on io and precedes the collections.
reactor
map
set
hamt
pvec
# gpu is host-side only (the Gpu effect, typed tensors, the fake device) and
# needs list, map, bytes and narrow; nothing in std uses it.
gpu
# memfs answers io's Fs from a table in memory: test support for any program
# that takes Fs, and the handler the compiler's own driver/fsmem moves onto one
# seed later (docs/fs-real-path-design.md). Nothing in std uses it.
memfs
