# The persistent corpus matrix for spike-native, one entry name per line in
# run order: every scripts/spike-native/*.dawn by basename, then every
# subdirectory holding a dawn.toml (a project entry, the only way to drive a
# real package). That is the same discovery run.sh does, and run.sh holds the
# two lists equal in both directions at startup -- a new corpus file nobody
# added here is red, and a line here with no file behind it is red.
#
# Why the list exists at all: the corpus is sharded across CI jobs
# (`--shard I/N`), and a shard that silently skips a slice prints the same
# PASS lines and exits 0 as one that did the work. Each shard records what it
# ran and scripts/mutant-coverage/check.py holds the union to this file. That
# checker says "mutant" throughout; it compares names and knows nothing about
# what a name denotes, so read the word here as "work item" -- a corpus entry
# missing from the union is exactly as unrun as a mutant missing from it.
#
# Round-robin sharding reads positions off this order, so reordering lines
# moves entries between shards (harmless, but say so in the commit if you do
# it on purpose). The order is the shell's glob order, which is what the
# transcript is replayed in.
