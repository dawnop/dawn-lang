# 具名值字段统一使用等号

> 状态：current。2026-10-23 落地过桥前端与离线迁移工具；发版、种子推进和全生态迁移另行完成。

## 规则与边界

最终语法使用 `f(gap = 12)`、`P { x = 1 }`、`P { ..p, x = 2 }`、
`K(x = p)` 与 `P { x = p, .. }`。pun `P { x }` 保持原样。
类型标注、字段类型与 bounds 继续使用冒号，例如 `x: Int`、`T: Show`。
调用位置的 `f(a = b)` 始终表示具名实参，不受外层局部变量影响；赋值仍只存在于语句位置。

种子尚不能读取新写法，因此本 release 临时接受两种值字段分隔符。
parser 只在一个判断函数中保留旧入口，不记录分隔符种类，不改 AST、落槽、默认值或求值顺序。
控制流头部的 `if x == None { result = 1 }` 保持赋值体；等号字段不能单独排除这种合法语句。
恢复仅在顶层字段逗号或闭括号后的头部/体 token 提供证据时认定误写的 record，
例如 `if x == P { a = 1 } { ... }` 仍报需加括号。
现有 selfhost、std、compiler-plan、packages 源码保持旧拼写，让上一代种子仍能编译本树。
下一 release 删除旧入口；不提供开关或弃用警告。

## 工具与迁移

fmt 保留输入分隔符，分别规范为 `x: v` 和 `x = v`，并正确对齐字段块与续行。
Show 与 LSP 的值展示使用等号；类型签名继续使用冒号。
LSP 对未完成调用同时识别两种标签，pun 展开生成等号并按 code point 计算新位置。

`scripts/named-arg-migrate/` 是下一轮迁移后删除的一次性离线工具。
它调用真实 parser，按 `Arg`、`ERecord`、`PatArg` 的名字跨度找到对应 token，
只改那个冒号，按倒序 code point offset 应用，不用正则替换源码。
完整模块与嵌入字符串分开列清单；字符串解码后的候选位置不能直接当宿主源码位置。
语法负例中被恢复丢弃的字段另作明确审阅项。
迁移器利用真实诊断把错误表达式位置的 `=` 暂替为等宽 `0` 后重解析，
恢复研究记录的三个丢失字段；原文件只应用被 AST 证明的冒号替换。

## 已验证的边界

迁移契约使用同一路径逐次写入两种写法，逐字节比较 AST、checker 与 Core dump。
未知名、重复名、位置后置、函数值与 Java 具名调用复用现有拒绝语料，检查两种写法诊断一致。
JVM/native 新语料覆盖乱序副作用、默认值读前参、spread 先求值以及具名构造/模式。
Unicode 补充平面字符、CRLF 与 pun offset 分别设断言。
三个负控先红再验正例：迁移类型冒号、把调用标签做成赋值块、fmt 互改分隔符。
新增 CI 步骤纳入 steps lock；不改变门禁预算或新增 job。

## 验收与交接

两种写法应有相同 AST、checker/core 结果、诊断与 JVM/native 求值顺序。
迁移工具必须保护类型冒号、字符串、注释及 pun，并证明二次迁移零修改。
迁移后的 scratch 副本由本 PR 编译器运行 selfhost 测试，fmt 再跑一次必须零 diff。
迁移 `std/` 并格式化后，必须在副本中运行 `python3 scripts/gen-stdsrc.py`，
同步嵌入标准库；否则现有的源文件与嵌入文本一致性测试会正确报红。
全仓 dry-run 按研究基线核对，dawnop-site 只读扫描。
刀 3 发布过桥版本并推进种子；刀 4 使用清单机械迁移、审阅嵌入片段，随后删除旧入口与工具。

## 不做的

- 本 PR 不迁移现有源码，不发布、不推进种子，不修改 dawnop-site。
- 不增加赋值表达式、表达式类型标注、内外双参数名或 kwargs 展开。
- 不改 ABI、默认值规则、spread 先求值或实参书写顺序求值。
- 不永久保留双语法，不让 fmt 自动转换分隔符，不批量改外语引述或 JSON/TOML/MLIR。
- 不以“同名局部禁止具名”规避 `==` 误写成 `=` 的风险。
