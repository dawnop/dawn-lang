# The SYN-05 mutant matrix: which assertions each mutant reddens, and which one
# of them owns it. Regenerate the red sets with
# `./scripts/pipe-contract/run.sh --record`; the `owner` lines are a hand edit,
# because which assertion owns a mutant is a design decision and a recorder
# that could reassign owners would launder the collision it exists to catch.
#
# Overlaps are recorded, not forbidden. A module-qualified call is an EMethod,
# so `drop-method-prepend` reddens `qualified` and the probe project too; the
# constructor mutant reddens only its own file. What may not overlap is an
# owner: `matrix.py` refuses a record in which two counted mutants redden the
# same owning assertion, which is what "owns" means.
#
# `negative-control-tighter-than-or` is recorded rather than counted. It builds
# and answers `--version`, but the bundled std stops parsing, so it reddens
# every assertion for a reason that has nothing to do with the pipe. It owns
# nothing and is excluded from the ownership rules.
