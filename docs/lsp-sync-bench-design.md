# LSP 同步延迟抽样：把复测固化成仓内脚本

> 状态：**current**：2026-10-19，分支 `lsp/sync-bench`。实现是 `scripts/lsp-sync-bench/`，
> 用法见同目录 README；实测数字回填在第五节。
> 依据：裁决「LSP 增量 sync 的验收线」（2026-10-19，两层线；第 6 条要求每次发版前跑一次抽样）、
> 同日的复测报告（场景 (a)(b)(c)、负载守卫、背靠背）与名级复用报告（PR #793，`check/types`
> 全部 `pub fn` 的测法）。三份都在仓库外的交接目录里，本文只引用其中的数字。

## 一、问题

裁决给 sync 定了第一条绝对线，并要求每次发版前抽样一次。可这些测法只存在于写者的
scratchpad 里（`lsp_remeasure.py`、`sample.py`、`pool.py`、`spool.py`），WSL 重启就没了；
每次复测都要重写一遍，口径也跟着漂（p90 的取法、要不要预热、交错还是先后跑）。
本文把口径定下来，脚本只照着做。

## 二、口径

- **被测物**：一个 jar 的 `lsp` 子命令，JVM 参数与 `bin/dawn` 的默认 `DAWN_JVM_OPTS` 相同
  （`-Xss512m -Xmx2g -XX:+UseSerialGC`）。不给 std 时不设 `DAWN_STD`，服务端用 jar 内嵌的
  std，也就是那个 release 自己的 std；种子与 HEAD 对照时各用各的。
- **工作区**：`<root>/selfhost`（默认本检出），打开 `main`、`front/ast`、`check/checker`、
  `check/types`、`driver/analyze`、`jvm/emit` 六个文件。编辑只经 `didChange` 发全文，不写盘。
- **sync**：从发出 `didChange` 到紧随其后的未知请求返回 MethodNotFound。服务端在回复前必须
  把待做的分析做完，所以 sync **不含防抖**，含整个工作区收敛（L-ws）。
- **edit**：从发出 `didChange` 到被编辑文件的 `publishDiagnostics` 到达（L-edit）。
  2026-10-20 起服务端在被编辑模块分析完时就发布它（`docs/audit/lsp-robustness-design.md`
  §2.2.6），此前是收敛后一次发完、edit 只比 sync 早几毫秒；脚本口径没变，这一列自己变了。
- **场景**（与复测报告相同，另加 (d)）：
  - (a) `driver/analyze` 的 `seg_ok` 体首插一行 `let`，体内编辑；
  - (b) `check/types` 的 `eff_suffix` 参数表末尾加、删 `l1_probe: Int = 0`，签名改动；
  - (c) `front/ast` 的 `arg_exprs` 体首插一行 `let`，体内编辑；
  - (d) `check/types` 末尾加、删一个 `pub type`，类型定义改动（改嫁接表，名级复用不覆盖它）。
    这是类型定义改动的**下界**：新类型没人用，不出诊断。
- **抽样**：`check/types` 的每个 `pub fn`（或按 `--sample N` 等距取 N 个）加、删同一个参数，
  每函数取各次的中位数，再对函数取中位数与 p90。这是名级复用报告 2.3 节的口径。
- **分位数**：最近秩，`sorted(v)[ceil(0.9 n) - 1]`，与 n 无关地落在真实样本上。复测报告的
  `pool.py` 用 `v[int(0.9 (n - 1))]`，n=42 时两者取同一个秩（第 37 个）。
- **预热**：每个会话先跑 `--warm` 轮（默认 3）不计入，与复测报告相同。
- **负载守卫**：每轮、每个抽样函数开始前读 1 分钟 loadavg，超过 `--load-max`（默认 4）就每
  `--load-poll` 秒（默认 20）再看，累计等待超过 `--load-timeout`（默认 3600 s）以状态 3 退出。
  每个样本记录发出时的 loadavg，JSON 里给出范围。阈值 4 沿用复测报告：它在 load 1.5 到 7
  之间测过，高于 4 的轮次离群明显。
- **对照**：`--baseline` 给第二个 jar 时，两个服务端同时起、同样预热，每轮（抽样时每个函数）
  两边各做一次同样的编辑，先后次序逐轮交换。配对差 = 本轮被测 − 基线，报配对差的中位数。
  同时起而不是一个会话接一个会话，是为了让两边落在同一段负载里：复测报告的交错是按会话
  交错，一个会话约 1 分钟，负载在这个尺度上会漂。
- **线**（裁决第 1 条）：只判被测 jar，不判基线。

  | 线 | 场景 | 量 | 上限 |
  |---|---|---|---|
  | L-edit | (a)(b)(c)(d)、抽样 | edit 的 p90 | 100 ms |
  | L-ws-body | (a)(c) | sync 的 p90 | 300 ms |
  | L-ws-sig | (b)、抽样 | sync 的 p90 | 300 ms |
  | L-ws-type | (d) | sync 的 p90 | 1000 ms |

  任何一条越线，退出状态 1；`--line NAME=MS` 可以临时改线（负控就是这么做的）。

## 三、为什么不进 CI

这是负载敏感的测量：复测报告里同一服务端的 (b) 在负载 2 到 4 之间五遍中位数差 34 ms，最坏值
因 full GC 到 1.4 到 2.2 s；托管 runner 与别的 job 共享机器，数字只会是噪声，红了也没人信。
它进的是发版清单（`docs/bootstrap.md` 的发版步骤）。

## 四、读源码的方式

脚本按字面定位编辑点（函数头、`pub fn` 列表），每个字面量必须恰好匹配一次，否则以状态 2
退出并说出是哪一个，所以登记在 `scripts/anchor-readers.txt`，类型 `self-once`：它不进 CI，
不该让一次与它无关的改名在 mutation-anchor-preflight 里变红；改名后由跑它的人顺手改锚点。

## 五、实测（回填，2026-10-19）

本机 16 核，HEAD `243afc49` 的 `build/dawn-selfhost.jar`，默认参数（6 遍 × 7 轮，150 个 `pub fn` 各 1 次加删），
全程包 `dcap`，没有触发负载暂停。单 jar 一次约 6 分钟，对照一次约 12.5 分钟。

| 场景 | 单跑 sync 中位 / p90（ms，load 1.3 到 3.3） | 对照：HEAD / v0.94.0（load 1.1 到 2.7） | 配对差中位 |
|---|---|---|---|
| (a) | 58 / 166 | 60 / 159 对 61 / 142 | −1 |
| (b) | 705 / 1325 | 677 / 1210 对 771 / 1167 | −90 |
| (c) | 32 / 115 | 31 / 45 对 31 / 32 | 0 |
| (d) | 652 / 850 | 630 / 785 对 728 / 1244 | −99 |
| 抽样（每函数中位数） | 666 / 917 | 662 / 917 对 751 / 1011 | −92（119/150 个函数 HEAD 更快） |

- 与复测报告（(b) 867 / 1419）和名级复用报告的基线（(b) 779 / 993，抽样 732 / 956）同量级；
  HEAD 比 v0.94.0 快约 90 ms，与 `78ca7dc3`（`line_col` 二分）在复测报告里实测的 −95 ms 吻合。
- (a)(c) 的 p90 落在 115 到 166，是复测报告记过的双峰（约 60 对 140，推测是 GC），中位数在 60 以内。
- edit 与 sync 在全部 540 个样本里都只差不到 1 ms，被编辑文件的发布都到了。
- 按今天的线，HEAD 越线的是：L-edit 全部场景（服务端还没有先发被编辑文件，(c) 的 p90 有时也过 100），
  L-ws-sig 的 (b) 与抽样（PR #793 合入前预期如此）。L-ws-body、L-ws-type 在线内。

第一版脚本里 (b) 与 (d) 各自从原文派生文本，互相抹掉对方的改动，四分之一的 (b) 样本发的是服务端已有的文本，
量出 35 ms。现在同一模块的各场景修订按场景组合（`compose`），自测里有这一条。

## 六、不做的（理由）

- **不进 CI**：见第三节。
- **不在服务端加计时探针**：复测报告的阶段拆分靠打补丁的服务端；发版前要量的是用户手上的
  那个 jar，补丁版的数字不是它的数字。要拆阶段时仍然照复测报告打补丁。
- **不做统计检验**：对照模式只报配对差的中位数和每边的分位数。裁决要的是「越没越线」，
  不是「差异是否显著」；样本量（默认每格 42）与复测报告相同，够看量级。
- **不量首次打开**：首次打开是另一条曲线（4 到 6 s），裁决没有给它线；JSON 里记了，不判。
