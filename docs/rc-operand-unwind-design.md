# 操作数临时引用的提前返回清理

> 状态：**current**。记录 issue #68 的操作数临时引用修复。

`out = out ++ [get(h)?]` 的第一个操作数由 `intr_args` 提升到临时绑定。
旧 `out` 可以转移给它，但临时绑定没有登记进 RC 作用域，因此第二个操作数
内的提前返回看不到它。消费检查器报告返回时还有活跃绑定。

实现是在求值后续操作数期间登记已提升的引用，并将这些引用加入后续操作数的
存活集合，避免普通语句清扫提前释放。操作数全部求值后，从作用域账本移出它们：
借用位置由现有包装器释放，拥有位置交给调用者。返回、break 和 continue
沿用现有作用域展开。没有新语法，也不改变 JVM 后端。

落点是 `selfhost/src/c/rc.dawn` 的操作数改写与消费检查测试，以及
`scripts/spike-native` 的成功、失败路径回归。验证包括修复前的负控、JVM/native
输出对拍和开启泄漏检测的 ASan，Core golden 只用正式脚本重录。

已验证：同一回归在修复前的 JVM 打印预期结果，而 native 编译在直线赋值和循环
赋值两处均报告返回遗留绑定；修复后 `spike-native/run.sh` 的对应条目全部通过，
包括非空堆列表上的失败路径。内联 RC 测试同时覆盖被提升的第一个操作数为拥有
和借用参数的两种调用模式，以及后续操作数中的正常语句清扫。

`dawn test selfhost` 594 项通过；源码循环标签与 Map 复用契约及其变异负控通过，
复用契约的正常直接更新与记录更新两条路径仍为 100%。Core 正式重录与检查通过
（17 份完整转储、87 个模块哈希）。除 `c.rc` 外，`compiler_plan.exitmem` 的
规范化哈希也移动：前面声明增长改变了生成的成对 handler ID 整数。
用父提交 `85e10bc7` 编译器和修复后编译器编译同一份源码，十个正式 JVM emit
语料逐字节相同，因此没有新增 `Emit-Change` 声明。

不做的：不改变赋值的最后使用转移优化，不把标准库已有递归绕行改回循环，
不扩展运行时清理协议；这里缺的是编译器已经生成的临时绑定的作用域归属。
