# tileiras wheel 缓存

> 状态：**current** —— issue #70 的实现方案；首次 CI 热缓存观测完成后回填预算依据。

四个 tile-golden 分片目前各自从包索引下载 toolchain.txt 固定的三个 wheel，网络超时会让尚未运行语料的分片失败。缓存只保存 wheel，键由 runner OS 与 toolchain.txt 内容摘要构成，不恢复虚拟环境，不设置跨版本回退键。

安装器接受可选 wheel 目录，省略时使用安装目录内的 .wheels。每次调用先核对固定版本对应的文件及 SHA-256，再决定能否复用已有安装；缓存命中不能绕过校验。缺失的 wheel 通过有重试上限和超时的 pip download 获取，安装始终用 --no-index --no-deps。安装后核对 Python 包版本及 tileiras 自报版本。

负控覆盖固定版本被改、哈希被改、缓存字节损坏，以及热缓存安装时禁止网络；工作流在分片一执行安装器契约。首次冷缓存 CI 只建立缓存，后续热缓存 CI 的实际步骤耗时才是预算回填依据，不预估节省多少秒。

不做：缓存 venv（避免恢复平台与解释器状态）、宽松 restore-keys（避免混用固定版本）、修改 tile 语料或编译器输出（与网络问题无关）。
