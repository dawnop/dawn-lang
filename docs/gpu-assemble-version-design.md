# 装配器版本身份的严格拒绝

> 状态：**current**。已实现的版本身份合同与验收要求。

`asm.assemble` 必须先识别装配器版本，再按版本、
目标架构和程序结构选择既有规避参数。错误身份会绕过精确版本表，因此
不能把任意非空的 `V` 后缀当作一个新版本。

## 版本文法

以已钉版本的真实输出为依据，接受恰好一条标准记录：

```
Cuda compilation tools, release <major>.<minor>, V<major>.<minor>.<patch>
```

三个版本分量都是非空 ASCII 十进制数，除单独的 `0` 外不允许前导零。
release 的两个分量必须与完整版本一致；不把后缀、额外字段或不完整版本
截断成已知版本。记录前后允许空格、制表符，接受 LF、CRLF、末尾无换行
及空白行。版权、构建等其他行可以存在，但包含 `, V` 或以
`Cuda compilation tools` 开头的行都必须满足上述文法。标准记录即使重复
且相同，也因身份不唯一而拒绝。

解析失败沿用 `UnknownVersion(output)`，逐字保留原始标准输出，并在发起
装配子进程前返回。解释文本说明无法找到唯一有效版本。合法的其他完整
版本仍走原有策略；不更改规避表、架构集合、break loop 判定或优化级别。
新供应商格式需要先补明确合同和夹具，不能猜测版本。

## 实现与边界

实现只涉及 `packages/tileir/src/asm.dawn` 的内部解析与同文件测试，
README 说明错误合同。公共函数签名、错误 variant、Tile IR 文本和字节码
保持一致。不涉及 lowering、设备程序、运行时或工具链版本。

## 验收

纯解析正控覆盖真实版本记录、另一合法版本、标准空白和换行；负控覆盖
乱码、分段缺失、截断、后缀污染、重复或矛盾记录、release 不一致和空输出。
fake executable 的装配分支创建哨兵：每个坏版本都必须返回带原始输出的
`UnknownVersion`，且哨兵不存在。恢复宽松解析的合法源码变异必须命中
这个断言。保留找不到执行文件、两个阶段非零退出、无 cubin 和清理用例。

用 fake executable 核对实际装配参数：已知版本的 break loop 仅在原有目标
集合使用既有规避；无 break、其他架构和合法其他版本保持普通参数。
完整 golden 包括装配、反汇编、重复 trace 和 JVM/native 对照，继承的文本
和字节码必须逐字节不变；真实 first 示例继续成功。按输入摘要重新录制
三个架构的完整账，并完成覆盖图要求的相关门和最终提交的完整外部门。
