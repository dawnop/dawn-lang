# Checks allowed to fail, each with the finding it records. Spike-native's
# ratchet rules: an unlisted failure is fatal, and so is a listed check that
# starts passing -- fix means delete the line and upgrade the expectation.
#
# All six coherent flips are red today, and the harness's first run is what
# found that. Two distinct findings:
#
# 1 (five sites): the call-site borrow REWRITE is correct -- with rc_module's
#   self-check bypassed, all five emit, print the expected bytes and run
#   asan+LSan clean -- but `rc_check`'s CCall arm still hard-codes the
#   all-owned convention (`chk_expr(c1, a, true)` for every argument; its
#   signature has no mode table), and `rc_module` panics on its verdict. So
#   ANY table row with a borrowed position is uncompilable today, right or
#   wrong. The checker extension was scheduled as part of knife 2
#   (perceus-design.md 6, oracle (2)); until it lands, these entries pin the
#   gap. When it lands they start passing, this ratchet fires, and the lines
#   come out.
#
# 2 (std/pvec:index): even with the checker fixed, this one stays red -- its
#   executed call sites are the `list_index` intrinsic, outside the table's
#   jurisdiction, so the coherent flip still leaks (measured: LSan direct
#   leak). The inference pass must refuse to stamp intrinsic-backed
#   functions borrowed on the callee side, or teach the intrinsic lowering
#   the same table. This entry holds that question open.
