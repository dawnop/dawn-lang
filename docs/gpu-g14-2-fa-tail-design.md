# G14-2 第四刀：库 FA 尾块

> 状态：**current**（已实现）。依据补裁二，保持既有 FA 数值策略，按分层 oracle 验收。

沿用前三刀已经验证的静态 view 边界：保留 `[bh,n,d]` 三维形状，Q 尾行由输出
view 屏蔽，K/V 读侧填零。仅在 `n % bk != 0` 的录制中，在 online softmax 的
最大值与指数运算之前将越界 key 列得分选成负无穷。零得分会进入 softmax 分母，
所以输入补零不能代替得分掩码。整除录制在宿主端跳过掩码，既有 golden 字节必须不变。

读者面只展示 bf16 输入、f32 累加的 FA。设备家族 `fatail` 使用各架构的计划，
覆盖两个 head、Q/KV 同时有尾、仅 Q 尾、仅 KV 尾。精确构造以等分数的 softmax
给出可精确表示的均值；正负分数、不同 head、不同列与 key 的值用来暴露跨 head
读写、分母错误与 extent 少一列。输出末尾留哨兵，输入末尾留毒值。

负控先证明会红：去掉负无穷掩码、输出 view 行数上整、有效 key extent 少一列。
依据补裁二，d=64/n=32、d=128/n=64 的 Q/KV 双尾单块构造分母为 2 的幂，
必须逐位精确；一般 n（含 255）逐 lane 相差至多 2 ulp，保持既有 approx div 策略。
数值负控必须超过该上界至少 1000 倍，或命中输出哨兵。三卡任一卡越过这些判据，
或任一既有 golden 字节变化，立即停止并回报。最终 inputs 变动后按指定顺序串行重录三卡，并核对既有家族摘要逐字符不变。

数值界依据：[PTX ISA 的 `div` 规范](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#floating-point-instructions-div)
规定 `div.approx.f32` 在分母绝对值处于 `[2^-126, 2^126]` 时最大误差为 2 ulp。
本构造的有效分数相等，指数权重为 1、被屏蔽权重为 0，求和均精确；分母为 32、64、192
或 255，结果也均为正常数，因此这里的 2 ulp 界只约束均值构造中最后一次除法。
分母为 2 的幂的两个隔离用例继续要求逐位精确。
