# Java class 元数据输入

> 状态：current

读取层为后续文档分析提供经过校验的原始 class 数据上下文。输入由版本绑定 manifest 和类目录组成。reader 按 JDK 21 正式格式校验长度、常量池、modified UTF-8、descriptor、成员与属性，并通过 Result 返回具名错误。上下文验证文件摘要、路径、重复定义、公开签名闭包和继承环，再保存不可变元数据。

格式解析放在 check 层，目录和 manifest 校验放在 driver 层。两层均使用现有 Bytes、JSON、SHA-256 和文件系统能力。测试通过现有 compiler/native 测试入口覆盖手构 class、损坏输入与目录负控，并由独立探针对照锁定 JDK 的原始字段。常量池 UTF、类名和已解析 descriptor 按索引共享，避免重复引用放大元数据分配。独立 probe 在 64 MiB JVM 堆中验证共享长 descriptor 的字段。输入上限为单类 16 MiB、8192 类、总计 128 MiB，数组维数上限 255。

native 元数据测试将 reader/context 内联测试、完整目录案例与签名分析探针并入既有编译器测试入口的一次编译，复用已制备的 native 编译器。这使新增模块的测试编译成本集中在同一程序中，减少重复工作。

结构读取、数据上下文与签名宿主已交付。文档命令通过显式元数据选项使用该上下文。旧 classread 的工具用途继续由原测试观察。JMOD 解包在制备阶段完成，运行时只读取绑定目录。

## 查询宿主设计

签名宿主直接消费已封印的 ClassMeta 表，保持现有八项 Jsig 查询与共享 checker 不变。目录构造后先预检目标的 Java import 根与完整公共签名闭包，再由 check 层的纯数据实现生成成员、继承和命名索引；成功才返回带 on 位的 lease。构造期的结构、缺类和资源上限错误继续使用 Result，查询不读文件、不执行 class、不吞错误。合同探针与原生文档命令在各自入口注入同一宿主。

完整分析探针放在已有命令入口层，反射工厂另置 JVM 专用入口。这样测试可调用同一 doc writer，又不让 checker 或下层合同模块依赖文档入口，保留既有门禁按模块图识别命令所有权的规则。

方法合并按公开声明、父类、直接接口遍历，保留实际 declaring owner 与返回类型，排除接口静态继承；桥接与 synthetic 筛选、SAM 的 Object 签名排除、数组协变及 primitive 名字的查询边界保持反射宿主规则。候选文案从原始 modifiers、参数、返回、throws 生成，遵循现有 Method/Constructor.toString 形状；checker 已有候选排序继续使用。Java 泛型仍按 descriptor 擦除，不引入新的类型推断。

每次 lease 独占不可变语义索引与有界查询缓存，同名类在不同数据上下文中不共享答案。构造时将图引用工作集与派生索引分别限制为 262144 行，合并成员前的临时集合也受同一上限约束；候选文案及 canonical 名称按 UTF-8 上界累计限制为 32 MiB，在拼接重复名称前计费，避免短输入用共享常量放大分配。达到限制返回具名 limit 错误；合法查询失配沿用 None/false。反射 oracle 与新宿主逐项比较全部字段、成员集合和重复项，另通过同一完整分析入口检查真实包、私有体和依赖测试。测试尽量复用既有编译器与测试编译，避免为分析探针再次编译整套编译器；门禁与预算仍使用现有步骤记录，不新增计时门。

## 文档命令接线

原生命令仅为 doc 增加独立值选项 `--java-signatures <manifest>`。早期参数扫描沿用从左到右的帮助与拒绝规则，选项的下一项保持不透明；重复选项及与 stdlib、builtins 的冲突在加载标准库前拒绝。其它命令继续按既有未知选项通道拒绝，不取得 Java 能力。

源目标仍由 native_load_target 捕获并消费同一次 SourcePlan。规划、装载和 Java 坐标拒绝保持优先于元数据错误；成功装载后收集全部模块的 Java imports，构造 metadata context 与预检 lease，再调用完整 analyze_program 和原 doc writer。没有选项仍使用拒绝宿主。元数据构造失败通过 rc 2 的单条具名诊断退出，源分析与文档错误保持 rc 1，不输出部分 JSON。manifest 相对当前目录解析，类目录相对 manifest 解析，不查询环境中的 JDK 或启动外部工具。

验收复用既有 native CLI 差分制备的编译器，以真实命令对照同提交 JVM 的全部包与标准库 JSON 原始字节，并覆盖参数优先级、损坏输入、私有体及依赖诊断。测试保留原门禁，不为该接线另建编译器或计时门；预算使用现有步骤记录。

预算取数后去除重复上下文构造：没有 Java imports 的包仍走正常 doc，Java 包显式提供绑定 manifest；另对一个纯包验证显式上下文与正常输出相同。将独立源码负控合入一次目录分析，保留每个错误模块的路径、错误片段及合法擦除返回模块不得报错的检查，再与 JVM 的整份诊断原字节比较。doc link 错误单独经过原 writer。这样保留全部逻辑案例、完整程序检查和十五份 JSON 资格，不为每个负控重新读取同一数据目录。

## 字节资格的独立预算与归属

完整 native doc 字节资格是刻意新增的验证步骤，独立放在 native-selfhost-tests；prev-diff-native 保留原 doc 差分及绝对 CLI 边界，不承接新全包资格。承接 job 原有七天最坏成功值 562 秒、原 claim 630 秒；规划另给新资格 120 秒，合计 750 秒，在 950 秒约束下留出余量。最终使用该新形态至少三次独立成功执行核验腿成本、整 job 最坏值及波动余量，push-total 的增加随提交明确记账。

将该 job 原先在 native-selfhost-tests.sh 内部执行的一次编译器制备原样提前到 workflow 的显式步骤，再以 DAWNC_BIN 交给原测试脚本；独立 doc 步骤直接使用同一 job、同一临时目录中的该二进制，不再构建或跨 job 传产物。新步骤从头执行全部十五份 JSON 和源码、数据负控，不接收 prev-diff-native 的 JSON 转录。原来仅服务同次差分复用的转录接口随之删除，保留 43 项逻辑断言与 36 次真实 native 调用。耗时只取既有 CI step 记录，不新增本机计时器。

## 不做的（理由）

通用 Maven 解析、JMOD 运行时读取、多版本 JAR 与 Java 执行属于其它能力。当前文档输入只需固定平台的原始元数据。
