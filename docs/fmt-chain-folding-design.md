# dawn fmt 的点链折行

> 状态：**current**。裁决见 2026-10-08 ruling-fmt-chain-folding；本文是刀 (a) 的设计与实现记录，
> 调研（rustfmt / Prettier / Dart 已核实源码，其余标 unverified）在 research-fmt-chain-folding。

此前 `dawn fmt` 没有行宽概念，作者写的物理换行一律保留，所以一行里挂五六个方法调用也不会折。
UFCS 风格让这种长链变多（ruling-ufcs-style 第 4 条），因此给格式器加一条**只管点链**的折行规则。
它不是通用行宽限制：没有链接点的长行仍然归作者。

## 规则

1. **触发只看宽度**：一条输出行（按格式器自己的间距与缩进算，码点数，行尾注释不计）超过 100 列，
   括号在本行内平衡且从不为负，不以闭括号、注释或 `use` 开头，并且在本行自己的括号深度上有至少一个链接点。
   不设调用数条件，也没有第二个 `chain_width`。100 取 rustfmt 的 `max_width`；它**只对链折行生效**。
2. **链接点**：`.f(`（`.` 后接标识符再接 `(`，三者同一物理行），前一个 token 是 `)`、`]`、`?`，或被判为后缀的 `!`。
   词法上 `list.map(xs, f)`（模块调用）与 `xs.map(f)`（方法调用）无法区分，所以紧跟在普通名字后的第一个 `.f(`
   不是链接点，留在链头。
3. **形状**：只折本行**最外层**的链，在每个链接点前换行，行首 `.`，缩进沿用已有的续行规则（+2）。
   括号内更深处的链接点不动。
4. **不碰作者的布局**：括号没在本行闭合的行（lambda 体、多行实参）、以闭括号开头的行、已经写成多行的链，
   一律原样保留；不合并（join）。
5. **幂等**：折出来的每一段都不再含本层链接点（它们全被断开了，行首 `.f(` 前面没有同行的 `)`），
   作者已折的链每行以 `.` 开头同理，所以 `fmt(fmt(x)) == fmt(x)`。
6. **实现**：`reflow` 在每个物理行的首个 token 处做一次前向扫描（`chain_folds`），用 `space` 模拟该行打印出来的宽度，
   把要断开的 `.` 的 `lo` 放进集合；之后遇到这些 token 时按作者写了换行处理。每个 token 的间隔换行数由
   `reflow` 开头的一次预扫描（`gap_newlines`）给出。不是两遍格式化，不改 lexer 与 parser。

## `?` 与 `!` 后缀

行首 `.` 续行在 parser 里早有先例，但 `x?` 与 `x!` 之后换行再接 `.f(` 此前没有实测。
`!` 与效果标记同一个 token，只有 `postfix_bang` 判为后缀的才算链接点（`fn f() -> Int !io` 的 `!` 不是）。
已用 `step(a, 1)?\n  .step(b)?` 与 `!` 版本编译并运行，折行前后语义一致；内联测试覆盖两种后缀。

## 对仓库的影响

超宽且含链接点的行实测 5 行（selfhost 的 checker、incremental、jreflect、lsprename；调研的正则近似给过 17，
多出来的多数是没有 `)` 前驱的头部调用），在同一提交里用 `dawn fmt` 重排。输出变化声明为 `Emit-Change(fmt)`。

## 不做的（理由）

- **调用数触发**（Prettier / ktlint 式）：会改写短而清晰的链，违背「保留作者换行」；词法层也数不准「调用」。
- **独立 `chain_width`**（rustfmt 的 60）：多一个宽度常量，而仓库本来没有行宽上限，一个数字就够。
- **合并作者已折的链**：格式器从不 join，保持幂等与低风险；gofmt、scalafmt 同样尊重作者。
- **折深层嵌套的链**：破坏幂等分析，收益接近零。
- **拆 lambda 或多行实参**：Prettier 为此堆了大量启发式，Dart 靠完整 AST 布局引擎，词法模型做不到不出错。
- **给链头的第一个 `.f(` 单独换行**：词法上分不清模块调用与方法调用，放在链头是唯一安全的判法。
- **`|>` 折行**：另行裁决（刀 (c)）。
- **完整 AST pretty-printer**：与现有词法模型的投入比不值得，且违反「格式器只需要词法成功」的前提
  （编辑器里未完成的缓冲区也要能格式化）。
