# 具名值字段统一使用等号

> 状态：current。2026-10-23 完成全仓迁移并删除旧入口；自举种子为支持双写法的 v0.99.0。

## 规则与边界

具名实参、record 构造与更新、构造器和 record 模式的具名字段使用 `=`：
`f(gap = 12)`、`P { x = 1 }`、`P { ..p, x = 2 }`、`K(x = p)`、`P { x = p, .. }`。
pun `P { x }` 保持原样。类型标注、字段类型与 bounds 继续使用冒号，例如 `x: Int`、`T: Show`。
调用位置的 `f(a = b)` 始终表示具名实参，不受外层局部变量影响；赋值仍只存在于语句位置。

旧值分隔符在 parser 中报错，诊断明确要求使用 `=`。没有开关、弃用警告或兼容分支。
控制流头部的 `if x == None { result = 1 }` 保持赋值体；
`if x == P { a = 1 } { ... }` 仍报告 record 需加括号。
旧拼写的头部 record 只为给出拒绝诊断而识别，不产生可接受的 AST。

## 迁移与工具

v0.99.0 是一次性的自举桥。迁移使用原 parser 的 AST 与 token 跨度，
只替换 `Arg`、`ERecord`、`PatArg` 对应的值冒号，再格式化并重新生成嵌入标准库。
二次 dry-run 必须零修改。错误恢复丢失的三个 grammar 字段同步迁移。
当前树已删除离线迁移器和对应 CI 步骤，保留标签与赋值区别、类型冒号和旧语法拒绝的常规测试。

Dawn 测试字符串、Python 与 shell 内嵌程序、LSP 会话和当前 Markdown 示例分别审阅。
签名简写、inlay 类型提示、历史引述和其它语言语法保留冒号；JSON、TOML、MLIR 的分隔符不动。
fmt 规范等号字段的空格、字段块与续行，不转换旧冒号。
Show 与 LSP 的值展示使用等号；类型签名继续使用冒号。
LSP 只识别等号标签，pun 展开按 code point 计算新位置。

## 不做的

- 不发布、不推进种子，不修改 dawnop-site。
- 不增加赋值表达式、表达式类型标注、内外双参数名或 kwargs 展开。
- 不改 ABI、默认值规则、spread 先求值或实参书写顺序求值。
- 不保留双语法，不让 fmt 自动转换旧写法，不批量改外语引述或 JSON/TOML/MLIR。
- 不以“同名局部禁止具名”规避 `==` 误写成 `=` 的风险。
