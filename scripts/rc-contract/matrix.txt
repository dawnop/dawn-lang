# Which assertions each production mutant reddens, and which one owns it.
#
# `assert` names the roster, in the order rc_test.c runs it, and `probe` the
# one poison_probe.c runs, in the order run.sh runs it. The two are separate
# rosters because they come off different builds -- the assertions off a
# plain one, the probes off a sanitized one with -DDAWN_SLAB_FORCE -- and a
# mutant is read off one or the other, never both. The red sets are observed
# by run.sh and compared with this file; the `owner` line is a hand edit,
# because which assertion owns a mutant is a design decision and a recorder
# that could reassign owners would launder the collision it exists to catch.
#
# Overlaps are recorded, not forbidden. `revert-adt0-to-fresh-allocation`
# reaches `none_is_shared` as well, because the runtime's own `None` goes
# through the same shared object. What may not overlap is the claim: two
# mutants may not name the same assertion as the one they own. An assertion
# can still be red under a mutant that does not own it, and one is
# (`slab_poisons_a_freed_block`, under both poisoning mutants), because a
# narrowed poisoning loses a strict subset of what a removed one loses.
#
# The controls are the assertions that stand closest to the mutations and
# must survive them anyway. `array_with` is the one reader of
# `dawn_is_unique` whose answer the singleton moves, and `immortal` is the
# pre-existing dup/drop guard the singleton reuses; a mutant that reddens
# either has stopped being about field-less constructors. `counts` and
# `sharing` are the same line for the allocator: every slab mutant below is
# still a working allocator, so a mutant that cannot count or cannot share
# has broken something other than the property it is named for.
# `slab_block_stays_clean_while_live` is the same line for the poisoning: a
# mutant that reddens it has made the sanitizer refuse a block the program
# is entitled to, which is a broken allocator rather than a lost report.
# The two cell assertions beside `cell_set_releases_the_old_value` are the
# same line for the state cells: `cell-set-forgets-the-old-value` is about a
# release and nothing else, so a mutant that also stopped `take` transferring
# or made `get` move a count would have changed the primitive rather than
# dropped one line of it.
#
# A `control` and a `benign` role are two different things. A control is an
# assertion that must survive every owning mutant; a benign mutant is an edit
# to a production file whose whole claim is that the *whole* roster survives
# it. The second is how a positive control gets written down: without a role
# of its own it would be indistinguishable from a mutant nobody ran.

# The bound and the retirement are one mechanism, so one mutant reddens both:
# a run that never hands a slab back has no retirements to count and no bound
# holding what it keeps. This is the mutant the knife rests on. Every answer
# the program prints under it is correct and every other gate in the tree
# stays green; the only thing that changes is that the memory never comes
# back, which is the whole reason the allocator was written.
role	slab-never-retires	counted
owner	slab-never-retires	slab_returns_pages
red	slab-never-retires	slab_returns_pages
red	slab-never-retires	slab_bound_is_honoured

role	slab-swallows-oversize	counted
owner	slab-swallows-oversize	oversize_leaves_the_slab
red	slab-swallows-oversize	oversize_leaves_the_slab
# Raising DAWN_SLAB_MAX grows the class table, and the idle budget literal
# (32MiB, written in rc_test.c rather than derived) reddens with it: a slab
# cache that swallows oversize blocks has also outgrown its documented bound.
red	slab-swallows-oversize	slab_bound_is_honoured

# The logical 64KiB slab and all of its transitions stay intact, but its first
# free list is laid out eagerly again. The contract-only logical observation
# reads 64KiB instead of 32KiB on every host; on a 4KiB-page host mincore also
# sees sixteen resident pages instead of eight.
role	slab-eagerly-materializes	counted
owner	slab-eagerly-materializes	slab_materializes_on_demand
red	slab-eagerly-materializes	slab_materializes_on_demand

# ---- a handler's state cells ----------------------------------------------
# The runtime's only overwrite, and so the only release that can be forgotten
# by omission rather than by a miscount. The mutant drops the `dawn_drop(old)`
# from `dawn_cell_set`; the program still computes the right answers and every
# other assertion here stays green, because nothing else in this file
# supersedes a value. What goes red is the count read off a second holder of
# the displaced value, which is the only vantage point from which a release
# that did not happen is distinguishable from one that did.
#
# It is a `counted` mutant, so the build carries no sanitizer and the leak
# itself is not what reddens: the assertion is. That is the point of having
# it -- under the sanitizer this would be one more unattributed leak report,
# and here it has a name.
role	cell-set-forgets-the-old-value	counted
owner	cell-set-forgets-the-old-value	cell_set_releases_the_old_value
red	cell-set-forgets-the-old-value	cell_set_releases_the_old_value

# ---- argument-carrying dictionaries ---------------------------------------
# Three mutants for one function, and what separates them is which of the
# three is a wrong answer: none of them. All three print what the unmutated
# runtime prints. The first holds more memory every call, the second hands
# back the wrong relation for a shape nothing in the tree constructs, and the
# third is only slower.

# The retreat: the interning finds nothing, so every call allocates again.
# This is the shape the runtime had until the leak was found, and outside
# this file it is scripts/wasm-dom-contract's plateau leg that reddens on it.
role	dict-intern-never-hits	counted
owner	dict-intern-never-hits	dict_is_shared
red	dict-intern-never-hits	dict_is_shared

# The key drops the arguments, so a family collapses to its first member.
# The memory still plateaus and every gate in the tree stays green, because
# no program here instantiates one template with two different arguments.
# `dict_family_is_keyed` is written out by hand for exactly this reason: it
# is the only thing anywhere that can tell.
role	dict-intern-ignores-args	counted
owner	dict-intern-ignores-args	dict_family_is_keyed
red	dict-intern-ignores-args	dict_family_is_keyed

# The `benign` role, and the only mutant in this file that must stay green.
# Every key hashes to zero, so the open-addressed table degrades to a linear
# scan. That costs time and nothing else, and a run that reddened here would
# be reading the probing rather than the identity -- which is what the two
# above are about. Recorded rather than omitted, because an untested green
# and an unexecuted one are the same empty red set.
role	dict-intern-hash-collides	benign

# The two below are the `poisoned` role: read off the probes, on a build with
# both the sanitizer and the allocator. Neither changes what a program
# computes, so run.sh also requires the whole assertion roster to stay green
# under them -- that is the control this pair has beyond the named one.

# Free blocks are no longer poisoned when they are handed back, so nothing
# outside a slab that is still being laid out is unreadable. Use-after-free
# and double-free on slab blocks stop being reported; the unissued neighbour
# is still covered, because the poisoning that covers it is dawn_sl_layout's
# and that one is untouched.
role	slab-forgets-to-poison	poisoned
owner	slab-forgets-to-poison	slab_poisons_the_whole_block
red	slab-forgets-to-poison	slab_poisons_a_freed_block
red	slab-forgets-to-poison	slab_poisons_the_whole_block
red	slab-forgets-to-poison	slab_catches_a_double_free

# The free block is poisoned from its ninth byte on, leaving the free list's
# link addressable. This is the mutant behind dawn_rt.c's argument for
# keeping the link inside the block at all: the claim is that ordering the
# calls the way it does leaves a free block poisoned including offset zero,
# and both probes below read offset zero -- the header of a freed object,
# and the count a second drop of it reads.
#
# Its red set is a subset of the one above, and has to be: narrowing the
# poisoned range can only lose reports that removing it also loses, so no
# probe could redden here and stay green there. What makes it a mutant of
# its own is the green it leaves behind. slab_poisons_the_whole_block still
# passes, so this is measurably a *narrowing* rather than a removal, and the
# two probes that go red are exactly the ones the argument names. That is
# also why the owner lines are the way round they are: the assertion the
# mutant above owns is the one only it reddens.
role	slab-leaves-the-link-live	poisoned
owner	slab-leaves-the-link-live	slab_poisons_a_freed_block
red	slab-leaves-the-link-live	slab_poisons_a_freed_block
red	slab-leaves-the-link-live	slab_catches_a_double_free
