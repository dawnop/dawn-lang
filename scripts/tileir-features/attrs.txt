# The Tile IR ATTRIBUTE ledger: one row per value of every attribute domain
# the dialect defines, and what this backend has done about it. Knife T4;
# ruling 6 of the full coverage prestudy (2026-09-05), which is recorded in
# docs/tile-backend-design.md 2.4, and the measurements in 6.8. Knife TG
# rewrote the three Global-record rows' evidence and their exemption after
# asking a device what the host can name in a module (6.13).
#
# This is the THIRD ledger in this directory. features.txt says which of the
# hundred public OPCODES this backend implements, types.txt which of the 23
# TYPE TAGS, and this one which values of the attribute domains it writes.
# They are three separate promises. An opcode can be implemented while the
# enum it carries has six values nobody has ever written, which is exactly
# the state knife T4 found and the reason this file exists. One check.py
# reads all three: the parser, the status / knife / layer rules and the
# evidence splitter are shared, and only the expected set and the evidence
# kinds are this table's own.
#
# The authority for the name, the code and the version is
# NVIDIA/cuda-tile@be0889cd:
# include/cuda_tile/Dialect/CudaTile/IR/AttrDefs.td for the six enum
# families and Ops.td for the unit attributes. A UnitAttr has no enum: it is
# present or absent, and its presence is a BIT in the flags word, so its
# `code` here is that bit and not an enum value.
#
# The `tag.*` family (knives T6 and T15) has a THIRD authority,
# include/cuda_tile/Dialect/CudaTile/IR/BytecodeAttrOpcodes.td: the twelve
# frozen ATTRIBUTE TAGS. AttrDefs.td says what an attribute means and that
# file says which byte announces it where one is written self-contained, so
# a `tag.*` row's `code` is the tag byte. Six of the twelve are here;
# `Integer` (1) and `Float` (2) are knife 3's reduction identities, which
# ruling 6's list leaves out for the reason it leaves out
# `ComparisonPredicate`, and the rest belong to attributes this backend
# does not write.
#
# WHAT IS NOT HERE. `ComparisonPredicate` (six values, all six written since
# knife 7a) and `Signedness` (two, both since knife 10) are enums whose
# value is chosen by the operation the caller asked for rather than by an
# attribute the caller could have set otherwise; they are the operation's
# name spelled twice and carry no coverage question, so ruling 6's list
# leaves them out and so does this file. `OptimizationHints` is a dictionary
# and not a domain of values, so knife T15 records it as its TAG and the tag
# of the `Dictionary` it wraps, and nothing else: the hint KEYS
# (`num_cta_in_cga`, `num_worker_warps_per_cta`, `occupancy`, `latency`,
# `allow_tma`) are not a domain either. Their values are ranges rather than
# an enum -- 1 to 32 for `occupancy`, 1 to 10 for `latency` -- so a row per
# value is not a thing this table could hold, and a row per KEY would claim
# a coverage no ledger here means: nothing checks a key (see
# `hints-do-not-change-answers` below), so "implemented" and
# "unimplemented" would name the same state.
#
# COLUMNS
#
#   feature     `<family>.<value>`, the dialect's own spelling of both
#   code        the enum value, or for a unit attribute the flags BIT it
#               sets in the operations that carry it
#   since       the bytecode version the VALUE entered: 13.1, 13.2 or 13.3
#   status      implemented | unimplemented | deferred, read as the other
#               two ledgers read them. `deferred` covers two situations
#               here and the exemption says which: `ruling 2` is the view
#               family, and `no-client-kernel` is a value the writer's own
#               table can already spell while no kernel asks for it (eight
#               of the ten atomic modes are in that state, and calling them
#               implemented would claim a coverage that does not exist)
#   knife       the knife that wrote the value first, or the knife the
#               prestudy plans it for; check.py's LANDED_KNIVES holds the
#               two directions, as it does for the other two ledgers
#   layer       the highest layer that covers it, 0 to 3
#   evidence    const:<NAME>    the constant in packages/tileir/src/bytecode.dawn
#                               that holds this value; its value is checked
#                               against the `code` column, which is what
#                               binds this file to the writer the way the
#                               OP_ table binds features.txt
#               writer:<fn>     the function in bytecode.dawn that writes
#                               the value, where it is a literal in a table
#                               rather than a named constant
#               golden:<kernel> a scripts/tile-golden kernel that carries
#                               the value. Unlike the type ledger's
#                               `golden:`, this is NOT held to the .mlir
#                               spelling it: most attribute values are the
#                               dialect's defaults and its printer leaves
#                               them out, so the text is silent about them
#                               by design
#               device:<kernel> a kernel a scripts/tile-gpu-diff program
#                               launches, whose answer DEPENDS on the value
#               mutant:<family> a mutant family that reddens on it
#   exemption   a named reason, where the bar of layer 2 is impossible
#               rather than merely absent, and `-` at or above the bar.
#               check.py holds both directions, as it does for types.txt.
#               An `unimplemented` row carries one only where the knife
#               column was REASSIGNED and the reason is not the plan's:
#               `13.3-record-field` is knife T7's three, handed to T8
#
# THE THREE LAYERS are docs/tile-backend-design.md 6.2, and layer 3 is read
# here as features.txt reads it: a mutant counts for a value when its anchor
# changes HOW THAT VALUE IS WRITTEN, not when it happens to go red on a
# device. That reading matters more here than for the opcodes, because an
# attribute value written wrong is usually still a legal program:
# `overflow<none>` where `no_signed_wrap` belongs assembles, runs and
# computes the same answer.
#
# A `device:` token is therefore a stronger claim than "the device ran this
# kernel". It says the ANSWER depends on the value: `attr_memsem` runs on
# the device and agrees, and none of its five ordering and scope values
# names it, because every ordering computes the same sums on a corpus with
# no race in it.
#
# THE NAMED EXEMPTIONS, in full:
#
#   assumption-not-arithmetic
#       `nsw`, `nuw` and `nw` tell the compiler what it may assume, and a
#       program that overflows under one of them is undefined. A corpus
#       that keeps the promise computes the same thing with the attribute
#       and without it; one that breaks it has no defined answer to compare
#       against. Ruling 1 of the prestudy names these three.
#       scripts/tile-golden's overflow-attr-not-written is the mutant, and
#       it goes red at layer 1: the assembler cannot parse a stream with
#       the attribute missing.
#       Ruling 1 names `assume` in the same breath, so knife T6's three
#       predicate tags (`div_by`, `same_elements`, `bounded`) are that same
#       argument in another family: with a true predicate the device
#       computes what it computed without it, and with a false one there is
#       no defined answer to compare. Their layer-1 mutants are
#       assume-divby-tag-as-same-elements,
#       assume-same-elements-payload-four-bytes and
#       assume-bounded-bounds-swapped.
#   tag-not-emitted
#       `String` (5) is the one tag this writer implements and never emits.
#       `assert`'s `message` and `print_tko`'s `str` are both `StrAttr`, so
#       the ODS getter answers a `StringRef` and `writeOpAttribute` takes
#       its own StringRef branch: the String section INDEX and no tag. A tag
#       byte only appears where an attribute is written self-contained, and
#       no operation here puts a string there. scripts/tile-golden's
#       assert-message-tagged is that sentence as a machine: write the 5 in
#       and `tileiras` answers `failed to parse attribute 'message'`.
#   no-race-in-corpus
#       A memory ordering and a memory scope constrain CONCURRENT accesses.
#       attr_memsem gives every lane its own slot and every block its own
#       384, so nothing races and every ordering computes the same sums. A
#       judgement about the ordering itself needs two blocks observing each
#       other and a comparison shape this repository does not have (the
#       exact tier compares one buffer after one launch). The mutant is
#       scripts/tile-golden's atomic-memory-attrs-swapped, red at layer 1.
#       `scope.device` is NOT exempt: leetgpu 13's histogram collides
#       across tile blocks, so a narrower scope would be a wrong answer,
#       and that is a device judgement.
#   global-bit-not-in-the-cubin
#       `alloca`'s `global` says the address may be handed to other tile
#       threads; without it the address is private to the one that made it.
#       A kernel that keeps its scratch to itself computes the same thing
#       either way, so the question is whether the bit reaches the machine
#       at all, and the answer is measured the way `fast_acc`'s was:
#       alloca_two's second allocation carries the bit and its first does
#       not, and setting BOTH moves exactly one byte of the `.tilebc`
#       (offset 56, 0 to 1) while `tileiras --gpu-name sm_86` writes a cubin
#       that is byte for byte the one it wrote before (measured, knife T10).
#       A bit that does not reach the cubin cannot make the device answer
#       anything else, so this is a measurement and not a missing kernel.
#       scripts/tile-golden's alloca-flags-unwritten is the mutant, red at
#       layer 1: it takes away the word the bit lives in.
#   fast-acc-not-in-the-cubin
#       `mmaf`'s `fast_acc` asks the hardware to accumulate at a lower
#       precision than the accumulator's format. It is the reason `mmaf`
#       writes a flags varint at all from 13.3 on, and knife T8 measured
#       what setting the bit buys on this machine: with the writer's word
#       changed from 0 to 1, ONE bytecode byte moves and the cubin
#       `tileiras --gpu-name sm_86` produces is BYTE FOR BYTE the same, on
#       all four `mmaf` kernels tried and on the f16 one as readily as on
#       the f64 ones (`matmul`, `batched_matmul_f16`, `attn_scores`,
#       `lora_hidden`). A device cannot answer differently for a bit that
#       does not reach it, so there is no layer-2 judgement here to be had
#       on this target rather than one nobody has written yet. What the
#       row does own is the flags word the bit lives in, and
#       scripts/tile-golden's mmaf-flags-unwritten is that: drop the word
#       and the assembler reads the first operand for it.
#   no-client-kernel
#       The writer's `rmw_mode_value` spells all ten atomic modes and only
#       two of them have a kernel. The table is right and nothing exercises
#       it, so the eight others are deferred rather than implemented.
#   ruling 2
#       The view family, deferred with the nine view opcodes until knives
#       T11 to T13 (docs 2.4). `PaddingValue` is a parameter of the view
#       TYPES (Types.td), not of any operation this backend emits.
#   visibility-not-in-the-lookup
#       `visibility.public` and `visibility.private` reach the CUBIN and
#       stop there, and knife TG measured both halves of that.
#
#       They reach it: `tileiras` gives a `private` global a LOCAL ELF
#       binding and a public one a GLOBAL binding, which
#       scripts/tile-golden checks on `global_syms`'s cubin (@shown and
#       @frozen GLOBAL, @hidden LOCAL, 1024 bytes each) and which
#       `visibility-private-written-as-public` reddens by forcing the
#       writer's enum to `public`. That is a judgement from outside this
#       repository about the VALUE and not about the record's shape, which
#       is why it replaced `global-visibility-omitted-at-13-3` on these two
#       rows.
#
#       They stop there: the dialect says public is "accessible from host
#       code" and private is "device-only access" (Ops.td's GlobalOp), and
#       on this machine the driver does not agree. `cuModuleGetGlobal`
#       answers ALL THREE of `global_syms`'s globals, at the right address
#       and 1024 bytes each; the host reads back what each declaration gave
#       them; the host WRITES all three; and the next launch computes with
#       what the host wrote. Declaring a global `private constant`, the
#       combination a compiler would have the most licence to fold, changes
#       none of it (measured, knife TG). So no device answer depends on
#       which of the two values was written, and the layer-2 bar is not
#       reachable here for a reason that was measured rather than missed.
#       scripts/tile-gpu-diff/sym_diff.dawn is that measurement, and it
#       runs `visibility-private-written-as-public` on the device as well
#       and holds it GREEN: if a driver ever starts hiding a LOCAL global,
#       that block goes red and this exemption gets revisited.
#
#       This exemption REPLACED `no-module-symbol-ffi`, which said the
#       judgement was one FFI operation away. Knife TG added the FFI
#       (`std/gpu`'s `module_global` over `cuModuleGetGlobal_v2`) and the
#       answer was not the one that sentence assumed. The FFI stays,
#       because the measurement is worth having and because it is what
#       keeps this exemption honest; the sentence is gone.
#   constant-not-in-the-cubin
#       `unit.constant` does not reach the machine at all, which is one
#       step short of the two rows above and is measured the same way
#       `fast_acc`'s was. With the writer's flag forced to 0,
#       `global_syms.tilebc` moves by exactly one byte at the same length,
#       `tileiras` accepts it, and the cubin it writes for sm_86 is BYTE
#       FOR BYTE the one it wrote before: a `constant` global lands in
#       `.nv.global.init` beside the mutable ones, with the same GLOBAL
#       binding and the same size. scripts/tile-golden's
#       `constant-flag-as-mutable` is that comparison as a gate rather than
#       a note, so a later `tileiras` that starts placing it elsewhere goes
#       red here instead of leaving this text quietly wrong. A bit that
#       does not reach the machine cannot make the device answer anything
#       else, and sym_diff says the same from the other end: the host
#       writes `@frozen` and the next launch reads the write, so it is not
#       read-only to the host either.
#   hints-do-not-change-answers
#       `optimization_hints` is a SUGGESTION, and ruling 1 of the prestudy
#       names it beside `assume` for exactly this reason: the dialect
#       promises that a hint does not change what a kernel computes, so no
#       corpus could tell one value of one from another by looking at a
#       buffer, and a `device:` token here would be a claim about the
#       ANSWER that no hint can support. Knife T15's hint_diff asks the
#       device the one question it can be asked -- do the hinted kernels
#       answer the bytes the unhinted `vadd` answers -- and it answers
#       yes, which is the promise kept rather than a dependence on a
#       value.
#
#       Layer 1 reaches the SHAPE and stops there, and that is measured
#       and not assumed. `OptimizationHintsAttr::verifyParamWithContext`
#       returns early unless `-Wunsupported-hints` is on, and it is off by
#       default: an unknown key (`occupancy_qqq`), an unknown architecture
#       (`sm_86a`) and an out-of-range value (`latency = 904`) each
#       assemble, exit 0 and print nothing. What IS refused is a count
#       that disagrees with what follows it, a tag that is not the one the
#       function table wants, and a flag bit in the wrong place, which is
#       what scripts/tile-golden's four hint mutants hold.
#
